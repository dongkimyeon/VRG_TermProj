# 스파인 단일 삭제 직접 확인 (2026-10-05)

사용자 스파인 **추가** 직접 절차 모두 정상 보고는 반영했다. 이번 **삭제** UI는 기존 클릭 도구 geometry unavailable 오류와 환경 변화 근거가 없어 재시도하지 않았다. 아래는 미검증 실제 입력 절차이며 FPS·장시간 운전 확인으로 확대하지 않는다.

## 직접 절차

1. 새 L_Test의 배치 모드에서 콘솔 `vrg.Layout.Save spine_before_delete`로 원배치를 보관한다. 콘솔을 닫고 기존 스파인 한 대를 클릭해 Delete한다. 해당 캐비닛·데이터 케이블/패치 배정은 사라지고, 연결 스파인이 없어진 줄은 미연결 진단이 남아야 한다. 랙과 냉각수 배관은 유지한다.
2. Ctrl+Z로 같은 위치·방향·설정의 한 대가 복원되고 Ctrl+Y로 다시 삭제되는지 확인한다. 다른 장비가 복원 위치를 차지하면 Undo는 거절되어야 하며, 그 장비를 비킨 뒤 같은 Undo를 재시도할 수 있어야 한다.
3. 스파인을 이동/R 회전한 뒤 삭제한다. 삭제 Undo 후 이전 회전/이동 Undo도 동작하는지 확인한다. 스파인 두 대나 랙+스파인 혼합 선택, 미선택, 드래그/사각형/추가 미리보기·패치 창·시뮬레이션 중 스파인 삭제는 거절되어야 한다. 기존 랙 다중 삭제는 그대로 지원한다.
4. 원배치를 Load하고, 스파인을 추가해 같은 Delete→Ctrl+Z→Ctrl+Y를 확인한다. 원배치 기존 스파인과 실행 중 추가 스파인 모두 단일 삭제를 지원한다.
5. 기존 스파인을 삭제한 상태를 `vrg.Layout.Save spine_deleted`로 저장한다. 원배치 Load→삭제 파일 Load 순서로 삭제 반영을 확인한다. 삭제 파일을 다시 Load해 추가 삭제/중복 생성이 없어야 하며 Ctrl+Z/Y가 이전 기록을 실행하면 안 된다. `spine_before_delete`를 Load하면 기존 스파인이 복원되어야 한다.
6. 새 L_Test 실행에서도 `spine_deleted`를 Load해 기존 스파인의 삭제가 반영되는지 확인하고, 원배치 파일로 복원한다. 저장 파일은 Saved/Layouts의 임시 파일이며 레벨 에셋은 변경하지 않는다.

결과는 기존/추가 스파인 Delete, Undo/Redo, 충돌 거절, 이전 이동/R, 입력 차단, 케이블/미연결, 저장 반복/기록 초기화, 새 실행 Load를 각각 정상 또는 관찰 결과로 알려주면 된다. 드라이버 안내는 아니오로 진행한다. 문제 시 입력 순서와 대상 종류를 함께 적는다.

## 자동화와 한계

Editor90.33s·저장 확장63.34s·검사 초기화 수정7.52s 성공. 입력3건 무경고 성공, 저장/결합6건 중5 성공/1 검사 초기화 오류 후 해당1건 무경고 성공으로 관련7종 성공을 확인했다. 신규 결합 검사의 열 기준을 기존 초기화 함수 호출 전에 읽던 오류만 수정했다. 기존 추가 결합 검사에는 CDU 없는 fixture의 가상 CDU 경고9건이 있다.

삭제 IT 감소2408.217600W/최대 상대오차1.511e-15, 전역 열수지 절댓값 최대1.713e-13, 덕트2.140e-15, 정규화 발산3.564e-08·압력 수렴. 원래 설정/초기조건에서 Undo/Load IT 복원 차이0W. 정확한 단위/정규화/기존 기준은 CLAUDE.md 최신 절을 따른다. 축소 NullRHI fixture 결과로 실제 L_Test 전체 운전/FPS를 보장하지 않는다.

새 저장 v2는 명시 deletedSpines로 기존 배치 스파인 삭제를 구분한다. 옛 v1/v2의 항목 누락은 기존 스파인 삭제로 해석하지 않는다. 열 상태·적분·시계는 저장/복사하지 않는다. 네이티브 단일 스파인 대상이며 다중 스파인 삭제/복제·Blueprint 재생성은 후속이다.
