# 웹 대시보드 계획 (2026-09-27 기록, 1단계 2026-10-13 완료)

실행 중인 시뮬레이션의 수치를 **브라우저에서** 보는 사이트다. 게임 화면에는 계속 단축키 안내만 둔다
(CLAUDE.md "화면 디버그 문구 끔"). 사이트는 화면 밖이므로 그 규칙과 충돌하지 않는다.
S7 남은 항목의 "결과 UI의 필요 범위 결정"을 이 계획으로 정한다.

## 사용자가 정한 범위 (2026-09-27 질의응답)

- 수치 묶음: **랙 내부 / 방 공기 / 냉각 설비·전력 / 센서·검증 상태** 전부.
- 데이터: **실시간으로 보고, 원하면 그 자리에서 리포트를 저장**한다.
- 보기 방식: **현재값 카드, 시계열 그래프, 평면도 뷰, A/B 비교**.
  A/B는 특히 **랙·CDU·쿨러(CRAH) 위치를 바꾸기 전후의 차이**를 보여 준다.
- 탭: **요약(발표·시연용)**과 **상세·검증(개발용)**을 나눈다.

## 탭 구성과 들어갈 수치

단위는 SI로 받고 사이트에서만 °C·kW·L/s로 바꾼다(규약 1·2). 모든 값에 `SimTime`을 붙인다(규약 4).

### 1. 요약 탭 (발표·시연)

- 상단 카드: SimTime, 모드(배치/시뮬레이션), IT 전력 [kW], 냉각 제거열(CDU/라디에이터 + CRAH) [kW],
  **부분 PUE**(시설 PUE가 아님을 옆에 적는다), 흡기 최고/평균 [°C], 27 °C 초과 랙 수, 경보 중인 센서 수.
- 평면도: 방을 위에서 본 그림. 랙·스파인·CDU·CRAH 발자국, 랙 색 = 흡기 창 평균(또는 현재값) 온도,
  CRAH 토출 방향 화살표, 콜드/핫 아일·컨테인먼트 판 표시. 랙을 누르면 상세 탭의 그 랙으로 간다.
- 시계열 3개: 흡기 최고·평균, IT 전력 대 제거열, 부분 PUE. 이벤트(`vrg.Eval.Event`) 시각을 세로선으로 표시.

### 2. 랙 탭

- 랙 목록 표: 이름, 줄, 부하율, 랙 발열 [kW], 흡기 [°C], 배기 [°C], 냉각수 입·출구 [°C]·유량 [L/s],
  서버 팬 속도비·전력 [W], 최고 부품 온도와 그 부품 이름.
- 랙 하나 선택 시: 슬롯(U) 높이별 막대 — 장비 종류, 슬롯 흡기 온도, 슬롯 발열.
  부품별 온도(Grace/Blackwell/RAM/VRM/NIC/E1.S/PSU 등)와 허용 온도 대비 여유 [K].
  노드가 613개라 전부 표로 뿌리지 않고 **슬롯 → 부품** 두 단계로 펼친다.
- 반출 분담: 냉각수 / 강제 공랭 / 자연대류 비율.

### 3. 방 공기 탭

- 공기 최저·최고·평균 온도, 최대 속도 [m/s], CFL, 난류 nu_t 최대·평균.
- 높이별 수평 단면 히트맵(바닥·랙 중간·천장 근처 등 몇 층). 격자 해상도 그대로(0.25 m 셀).
- 흡기 표: 랙별 현재값·창 평균(기본 마지막 100 s)·실행 최고·27/32 °C 초과 시간.
- 핫스팟 위치(최고 온도 셀 좌표 m). **0.25 m에서 랙별 흡기는 격자 수렴하지 않았다**(CLAUDE.md 격자 수렴 절)는
  주의 문구를 이 탭에 고정으로 붙인다.

### 4. 냉각 설비·전력 탭

- CRAH 유닛별: 풍량 [m³/s], 흡기 혼합·토출 온도 [°C], 제거열 [kW], 팬 전력 [kW], 코일 UA.
- CDU 줄별: 부하 [kW], 회수·공급 온도, 설비수 입·출구 온도·유량, 설계 부하 대비 비율(포화 여부).
- 펌프: 유량 [L/s], 양정 [kPa], 전기 입력 [kW], Newton 반복·수렴 여부. 분기별 유량 편차.
- 전력 분해 누적 막대: IT(부품 / 서버 팬 / PSU 손실) + CRAH 팬 + 펌프 → 부분 PUE.
  모델에 없는 것(칠러·냉각탑·CDU 펌프·UPS·조명)을 같은 칸에 적는다(D8).

### 5. 센서·검증 탭 (개발용)

- 가상 센서 표: 판독값, 참값(격자값)과의 차, 경보 상태, 첫 감지 시각, τ·주기·σ·분해능.
  제목에 "모의 계측값"을 적고 신뢰도 100%로 표기하지 않는다(D9).
- 전역 열수지: 유입·유출·축적과 정규화 잔차, `DescribeEnergyLedger` 분해(랙 / 공기 / 냉각수 결합 / 공기 결합 / 고체 버림).
- 솔버 상태: 압력 반복 수·정규화 잔차·수렴 실패 누적 수, CPU/GPU 경로, 격자 크기·셀 수.
- 성능: Frame 중앙값·P95, Game/Draw/GPU, 스텝 비용과 단계별 분해. "측정값이며 보장값 아님"(D10).

### 6. A/B 비교 탭

- 저장한 리포트 두 개를 고른다(기존 `vrg.Eval.Report` / `vrg.Eval.Compare` 형식 재사용).
- **배치 차이**: 두 평면도를 나란히 + 옮긴 장비를 화살표로(이동 거리 m, 회전 도). 기존 `vrg.Layout.Save` JSON에서 읽는다.
- **결과 차이**: 랙별 흡기 창 평균 차 [K]를 평면도 색으로, 방 평균·최고·초과 랙 수·제거열·부분 PUE 차.
- IT 부하가 0.1% 넘게 다르면 경고를 띄운다(D8: 같은 IT 부하에서만 비교).
- 인로우 구성은 같은 설정도 최고값이 약 0.5 K 흔들리므로 그 이하 차이는 "구분 불가"로 흐리게 표시한다.

## 3D 시각화 참고 이미지 (2026-09-27 사용자 지정)

**3D 방 보기는 `1749770467305.png`(저장소 루트, 아직 커밋 안 됨) "Spatially-enabled Digital Twin" 이미지를 참고해서 만든다.**
- 어두운 배경, 방을 비스듬히 위에서 본 아이소메트릭 3D. 벽은 낮게 잘라 안이 보이게 한다. 장비는 무채색 덩어리.
- 방 위에 **색으로 칠한 흐름 띠**(파랑→초록→노랑→빨강)를 얹어 흐름과 온도를 함께 보인다. 이 프로젝트에서는 기류·냉각수 흐름에 쓴다.
- 바닥에 번지는 **온도 얼룩(heat glow)**으로 뜨거운 곳을 보인다.
- 이상 지점에 **경고 삼각형 + 지시선 라벨**. 센서 경보, 흡기 초과 랙, (S2b 이후) 누수 지점에 쓴다.
- 왼쪽에 **KPI 카드**와 작은 **히트맵 + 색상 막대**. 요약 탭의 카드·단면 히트맵이 이 배치를 따른다.
- 이미지를 그대로 베끼지 않는다. 흐름 띠를 그릴 때는 계산 결과(속도장·수력 유량)에서 뽑은 것인지, 설명용 도식인지 화면에 구분해 적는다.

**데모 (2026-09-27):** 방향 확인용 정적 페이지를 만들었다(three.js, 저장소 밖 claude.ai 아티팩트).
랙·스파인 위치, 흡기 창 평균, 센서 경보, 전력·부분 PUE, 열수지는 `Saved/Reports/ContNone.json`·`ContRoof.json`의 **실제 계산값**이다.
벽, CRAH·CDU 위치, 흐름 띠, 배관 경로, 누수는 **도식**이며 화면에 "도식" 표시를 붙였다. 실제 대시보드에서는 이 도식들을 계산값으로 바꾼다.

3D 보기에 나중에 얹을 층 (켜고 끄기):
- 센서 위치와 판독값(모의 계측값, D9), 경보 상태.
- 냉각수 배관과 유량(수력 해), CDU·CRAH 위치와 토출 방향.
- **누수 (S2b 이후)**: 누수 지점, 누수 유량(`Cd·A·√(2Δp/ρ)`), 영향 범위는 **네트워크 재계산 결과로만** 칠한다(D4).
  밸브 격리 범위와 수력 영향 범위를 다른 색으로 구분한다.

## 구조 (제안, 착수 시 확정)

- UE 쪽: 엔진 `HTTPServer` 모듈로 로컬(127.0.0.1) HTTP 서버를 연다. Build.cs에는 **실제로 쓸 때** 넣는다.
  - `GET /api/snapshot` — 현재값 JSON. `GET /api/series?since=<SimTime>` — 시계열 증분.
    `GET /api/layout` — 평면도 기하. `POST /api/report?name=` — 지금 상태로 `vrg.Eval.Report` 저장.
    `GET /api/reports`, `GET /api/report/<이름>` — 저장한 리포트 목록·내용(A/B용).
  - 규약 5: 게임 스레드가 스텝(또는 0.5~1 s)마다 **표시용 스냅샷 사본**을 만들어 둔다. HTTP 스레드는 그 사본만 읽고
    액터·UObject·솔버를 조회하지 않는다. 기존 `GetDisplaySnapshot`(시뮬 시간당 한 번 생성)을 재사용한다.
  - 시계열은 게임 스레드에서 고정 간격(SimTime 기준 1 s)으로 링 버퍼에 쌓는다. 실행 중 저장 리포트와 같은 창 정의를 쓴다.
  - 단면 히트맵은 셀 전체(수만~수십만 개)를 매번 보내지 않고 요청한 층만, 낮은 빈도로 보낸다.
- 사이트: 빌드 도구 없는 정적 HTML/JS 한 묶음(`Web/` 폴더 제안)을 같은 서버가 내준다. 1 s 간격 폴링으로 시작한다.
  WebSocket은 폴링이 부족하다고 측정된 뒤에 검토한다.
- 켜고 끄기: 콘솔 `vrg.Web.Enable 0|1`, 포트 `vrg.Web.Port`(기본값은 착수 시 정함). 기본 끔 여부는 성능 측정 뒤 정한다.

## 지켜야 할 것

- 사이트는 **보여 주기만** 한다. 사이트에서 물리 입력을 바꾸지 않는다(첫 범위에서는 리포트 저장만 쓰기 동작).
- 보존 잔차가 작다는 표시를 "실제 온도가 맞다"로 읽히게 하지 않는다. 요약 탭 아래에 "보정되지 않은 모델" 문구를 둔다.
- HTTP 스냅샷 생성 비용을 계측(`VRG_SCOPE_COST`)에 넣고, 켰을 때와 껐을 때 프레임을 재서 기록한다(D10).
- 외부 네트워크에 열지 않는다(127.0.0.1만).

## 검증 계획

- 자동화: 스냅샷 JSON 직렬화 → 역직렬화 왕복, 값이 솔버·장부 값과 같은지(단위 변환 포함), 시계열 SimTime 간격이 빠짐없이 이어지는지,
  리포트 저장 API가 `vrg.Eval.Report`와 같은 파일을 만드는지, A/B 배치 차이 계산(이동·회전).
- 수동: L_Test에서 브라우저로 각 탭 확인, 배치 바꾸기 전후 리포트 두 개로 A/B 탭 확인.
- 성능: 서버 켬/끔 프레임 중앙값·P95 비교.

## 정하지 않은 것 (착수 전에 물어볼 것)

- 시계열 보관 길이(예: 최근 600 s)와 간격.
- 단면 히트맵 층 수·갱신 빈도.
- 포트 번호, 기본 켬/끔.
- 리포트 저장 때 시계열 전체도 CSV로 함께 남길지.

## 1단계 결과 (2026-10-13)

범위: 요약 카드 하나(SimTime, IT 전력, 제거열, 부분 PUE, 흡기 최고/평균)만. 평면도·시계열·랙 탭·A/B·리포트 저장 API는 하지 않았다.

- 서버: 엔진 `HTTPServer` 모듈(Build.cs에 이번에 추가), `Config/DefaultEngine.ini [HTTPServer.Listeners] DefaultBindAddress=127.0.0.1`.
  콘솔 `vrg.Web.Enable 0|1`(기본 **0**), `vrg.Web.Port`(기본 **18080**). 코드 `Source/VRG_TermProj/UI/VrgWebDashboard.*`.
- 경로: `GET /api/snapshot`(JSON, 첫 값 전에는 503), `GET /dashboard`(저장소 `Web/index.html`). 엔진 라우터는 `/`를 묶을 수 없다
  (`FHttpPath::IsValidPath`가 루트를 거부, 처음에 assert로 죽었다). 응답은 `Cache-Control: no-store`.
- 규약 5: `ADataCenterSimulationActor::PublishDashboard()`가 Tick 끝(스텝 뒤)에서 실시간 0.5 s마다 `FVrgDashboardSummary`를 만들어
  JSON 문자열 사본을 잠금 아래 넘긴다. 핸들러는 그 문자열만 읽고 액터·UObject·솔버를 보지 않는다. 사이트는 읽기 전용이다.
- 단위: JSON은 SI(W, K, s). 페이지에서만 kW·°C로 바꾼다(규약 1·2).
- 값의 출처: 창 평균(IT, 부분 PUE, 흡기 최고/평균)은 리포트와 **같은 함수**(`FVrgEvaluation::GetWindowPower/GetPartialPue`,
  새로 뺀 `GetInletWindowSummary` — 리포트도 이걸 쓰도록 바꿨다). "현재" 값(IT, 제거열 = 냉각수 방출 + 공기 코일)은 같은 SimTime의
  결합 스냅샷이며 HUD와 같은 시뮬 시간당 1회 캐시(`GetCachedDisplaySnapshot`)를 쓴다.
- 계측: 요약 생성 비용을 `VRG_SCOPE_COST(STAT_VrgDashboardPublish, DashboardMs)`로 잰다. Perf CSV에 `DashboardMs` 열, txt에 프레임당 평균을 추가했다.

검증:
- `VRG.Web.DashboardSummary`(신규): JSON 왕복 정확 일치, 창 값 = 같은 SimTime의 리포트 JSON 값(정확 일치, 흡기는 K−273.15),
  현재 값 = 스냅샷, 배치/시뮬레이션 모드 구분, 서버 끔→발행 없음 / 켬→포트 바인딩·Tick 발행 사본 = 요약 / 다시 끔→중지·비움.
  `VRG.Eval.RerunEventsAndReport`(리포트 경로 변경 영향) 성공. NullRHI. 전체 Automation은 돌리지 않았다.
- Editor `-game`(DX12 1280×720, `vrg.Web.Enable 1`, 1500스텝 예열) 한 번: 로그 "대시보드 시작: http://127.0.0.1:18080/dashboard",
  `/api/snapshot`이 SimTime 85 s의 값(IT 3757.0 kW, 제거열 3431.5 kW, 부분 PUE 1.0099, 흡기 34곳)을 냈고 페이지 카드가 1 s마다 갱신됐다
  (브라우저 창에서 확인). 같은 실행의 30 s 리포트 IT 3755.2 kW·잔차 -1.30e-14는 기존 기준과 같다(물리 경로 변경 없음).
- 비용: 10 s 수집 중 발행 19회, 1회 최대 0.0133 ms·평균 0.0061 ms(이 PC). 서버 켬/끔 프레임 비교는 하지 않았다
  (생성 비용이 프레임의 0.1% 미만이라 실행 간 편차에 묻힌다). 측정값이며 보장값이 아니다(D10).

한계·다음:

### 4단계에서 발견한 관리 스위치 과열: 원인과 수정 (2026-10-13)

## 랙 탭 JSON 비용 수정 (2026-10-13)

5단계에서 기록한 "랙 탭 요청당 약 4.1 ms"의 원인을 측정으로 나눴다. 거의 전부 **고른 랙 상세(부품 613개)의 JSON**이었다.

남겨 기준 구현과 진단 비교에 쓴다. 문자열은 따옴표·역슬래시·제어문자를 이스케이프한다.

## 냉각 설비·전력 탭: 서버 쪽 (2026-10-14, 페이지 미완)

`GET /api/cooling`: 이미 계산된 값만 복사한다(새 물리 없음). CRAH 유닛별 풍량·UA·팬 전력·냉수 공급 온도와 **흡기 혼합·토출 온도·제거열**
(공기 솔버 CPU 균일 경로가 덕트 코일 계산 지점에서 기록, GPU/옥트리 경로에서는 null), CDU 줄별 설계 부하·UA·설비수 유량/입출구·부하·회수/공급·고온측 열용량률,
펌프 줄별 유량·양정·전기/수력 입력·분기 유량 최소/최대/평균, Newton 반복·잔차·수렴, 전력 분해(IT = 부품 + 서버 팬 + PSU 변환 손실, CRAH 팬, 펌프)와 이번 스텝 부분 PUE.
PSU 손실은 랙 모델이 이미 계산하던 값을 `GetLastConversionLossW()`로 기록만 한다.

검증 `VRG.Web.CoolingMatchesModel`(NVL72 2랙·CDU·인로우 CRAH 2대, 1 s): IT = 노드 발열 합, PSU 손실 = 손실 비율 × DC 부하(상대 4.7e-16),
유닛 제거열 합 = 솔버 덕트 코일 합(1.4e-16), 유닛별 ε-NTU 식(3.8e-15)·엔탈피 식(1.4e-16), CDU 부하 = 양쪽 엔탈피 변화(1.6e-15), 분기 합 = 펌프 유량(0), JSON 왕복.
영향 테스트 13건 성공(3건은 엔진 HTTP 타임아웃 경고만). **남은 것: 페이지 탭(표·누적 막대·모델에 없는 항목 표시), Editor -game 확인.**

## 일시 중단: S2b 먼저 (2026-10-20)

팀장 결정으로 S2b(누수·재고·밸브·장애)를 먼저 한다(`Tools/S2b_누수_계획.md`). 이 문서의 남은 탭(냉각 설비·전력 페이지, 방 공기, 센서·검증)과
패키징은 S2b 뒤에 누수 레이어와 함께 이어 간다. 냉각 설비·전력 탭은 서버 `/api/cooling`과 테스트만 커밋돼 있고 페이지는 아직 쓰지 않는다.
