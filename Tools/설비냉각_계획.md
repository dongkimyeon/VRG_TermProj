# 설비 냉각 계통 계획 (S8, 2026-10-15)

## 왜 필요한가

지금 모델은 건물 안쪽에서 끝난다. 열이 빠져나가는 곳이 "온도가 고정된 무한한 물"이다.

| 지금 경계 | 코드 | 문제 |
|---|---|---|
| CDU 설비수 공급 22 °C 고정, 유량은 설계 부하에서 역산 | `CduHeatExchanger.h` `FacilitySupplyTempK` | 외기·열원 용량·설비 펌프와 무관 |
| CRAH 코일 냉수 18 °C 고정, 냉수 쪽 열용량률 무한(C_r → 0) | `DataCenterSimulationActor.h` `CoilSupplyTempK` | 냉수 유량 한계·밸브 제어 없음 |
| 부분 PUE = (IT + CRAH 팬 + CDU 펌프) / IT | `VrgEvaluation.h` | 칠러·드라이쿨러 팬·설비 펌프가 없음 |
| CDU 펌프 손실열의 분배 없음 | 기존 부채 | 전역 장부가 IT + CRAH 팬 입력 기준 |

디지털 트윈이므로 실제 데이터센터 설비 계통의 구조(루프 분리, 장비, 제어, 이중화)를 따른다.
외기가 더워지거나 열원 장비가 멈추면 랙 흡기·칩 온도까지 결과가 이어져야 한다.

## 실제 구조 (용어는 ASHRAE TC 9.9)

```
[랙 콜드플레이트] ─TCS─ [CDU] ─FWS(온수)─ [설비 펌프] ─ [드라이쿨러 + 팬] ─ 외기
                                                  └(외기가 더우면) [트림 칠러]
[CRAH 코일] ─CHW(냉수)─ [냉수 펌프] ─ [칠러 증발기]
                                        [칠러 응축기] ─CW(응축수)─ [드라이쿨러 또는 냉각탑] ─ 외기
                      └ [수측 이코노마이저(판형 열교환기)] (외기가 차가우면 칠러 대신/앞에)
```

- **TCS** (Technology Cooling System): 랙 ↔ CDU 2차측. **이미 있다**(인로우 루프, Newton 수력, CDU ε-NTU).
- **FWS** (Facility Water System): CDU 1차측 ↔ 열원. GB200급 액랭은 고온수(W32~W45 등급)를 쓰는 경우가 많아
  외기가 충분히 차가우면 칠러 없이 드라이쿨러만으로 식힌다(free cooling). 더운 날을 위한 트림 칠러는 선택.
- **CHW** (Chilled Water): CRAH 코일 ↔ 칠러 증발기. 공기 쪽은 액랭보다 낮은 물 온도가 필요하다.
- **CW** (Condenser Water): 칠러 응축기 ↔ 열 방출 장비.
- 분배: 공급·회수 헤더, CDU·CRAH 앞 2방 제어 밸브, 차압 유지(바이패스 또는 펌프 회전수 제어), 장비 이중화(N+1).
- 위치: 칠러·펌프는 기계실, 드라이쿨러·냉각탑은 옥상/야외. **방 공기 격자 밖**이며 외기 조건만 경계로 받는다.

**결정 (2026-10-15, 사용자 동의):** 기본 구성은 FWS와 CHW를 나누는 **분리**다. 응축 열 방출 기본은 **드라이쿨러**(습도 모델 불필요).
냉각탑(습구온도 필요)은 후속 선택지로 남긴다. 실제 시설에 있는 **공용 냉수**와 **직렬(캐스케이드)** 구성도
같은 코드로 선택해 시뮬레이션·비교할 수 있게 한다(아래 절, 2026-10-15 사용자 요청).

## 설비 구성 세 가지 (선택해서 비교)

CDU와 CRAH가 어떤 물을 받는지만 다르고, 나머지 장비 모델(펌프·밸브·칠러·드라이쿨러·외기)은 공통이다.
구성은 **설비 망을 만드는 빌더의 입력**이다. 장비 모델이 구성마다 따로 있으면 비교가 공정하지 않다.

| 구성 | 루프 | CDU 1차측 입구 | CRAH 코일 입구 | 칠러가 맡는 열 | 실제로 쓰이는 곳 |
|---|---|---|---|---|---|
| 0 분리 (기본) | FWS 온수 + CHW 냉수 + CW | FWS 공급(드라이쿨러, 더우면 트림 칠러) | CHW 공급 | 주로 공랭 열 | 액랭 위주 새 시설 |
| 1 공용 냉수 | CHW 하나 + CW | CHW 공급 | CHW 공급 | 공랭 + 액랭 전부(이코노마이저가 덜어 줌) | 냉수 설비만 있던 기존 건물에 액랭 랙 도입 |
| 2 직렬 (캐스케이드) | CHW 하나 + CW | **CRAH 코일을 지나 데워진 CHW 회수** | CHW 공급 | 공랭 + 액랭 전부, 대신 회수 온도가 높아 COP 유리 | 한 루프로 두 온도를 쓰려 할 때 |

구성별로 망에서 달라지는 것:

- **분리:** 두 루프가 수력·열적으로 독립이다. CHW 설정을 바꿔도 FWS 해가 바뀌지 않아야 한다.
- **공용 냉수:** CDU 1차측과 CRAH 코일이 같은 공급 헤더에 **병렬**로 붙는다. 유량은 각자의 2방 밸브가 나눈다.
- **직렬:** CRAH 코일 회수 헤더 → (혼합 노드) → CDU 1차측 → 칠러 회수. 두 부하의 유량이 직렬로 묶이므로
  유량·ΔT를 맞추는 **바이패스(3방) 밸브**가 필요하다. 혼합 노드의 온도는 한 번 계산해 CDU 입구로 그대로 쓴다(규약 6).
- 세 구성 모두 같은 TCS·랙·공기 모델을 쓴다. CDU 2차측(TCS) 공급 온도는 CDU 1차측 입구 온도에 따라 결과로 정해진다.

**공정한 비교 규칙 (D8):**

- 같은 랙 배치·부하·외기 조건·시간 프로파일·시드로 돌린다(기존 S6 재실행 규칙).
- 장비 용량은 **구성마다 같은 설계 규칙**(설계 외기 온도, 설계 부하, 접근온도)으로 크기를 정한다.
  한 구성만 넉넉한 칠러를 받지 않게, 설계점과 결과 용량을 리포트에 함께 적는다.
- 전력은 모두 운전점(`Δp·FlowM3s/η`, 칠러는 COP 곡선)으로 구한다. 정격 × r³을 쓰지 않는다.
- "어느 구성이 더 효율적이다" 같은 순서를 테스트에 하드코딩하지 않는다. 순서는 비교 결과로 보고, 검증 규칙대로
  상대 비교도 검증 대상이다. 테스트가 거는 것은 보존과 닫힌 해, 극한 사례뿐이다.

## 지켜야 할 규칙과의 관계

- 규약 6: CDU가 구한 duty를 TCS·FWS 양쪽에 **같은 값**으로 쓴다. 칠러는 `Q_cond = Q_evap + W_comp`를 한 번에 구한다.
- 규약 4: 설비 계통도 같은 `SimTime`을 적분한다. 배관·장비 물 체적의 열용량으로 지연을 둔다(D2, 준정상으로 덮어쓰지 않음).
- D2: 유량 0에서 `HeatW/(ṁ·cp)`를 계산하지 않는다(펌프 정지·밸브 닫힘).
- D3: 설비 배관도 노드 압력 Newton. 노드 200개 초과 시 기존 Eigen SparseLU 경로.
- D5: 제어 루프(팬 속도, 밸브, 칠러 단계)는 정규화 잔차/상한과 실패 표시를 갖는다.
- D8: 팬·펌프·압축기 전력은 운전점에서 구하고, 정격값이 축동력인지 전기입력인지 근거마다 명시한다.
- D4/S2b: 누수·장애는 이 설비 배관 위에서도 재계산으로 판정한다. 그래서 **S2b는 이 단계 뒤**다.
- "보이는 것 = 계산하는 것": 화면의 설비 배관·장비는 수력망이 푸는 것만 그린다.
- 새 물성은 공개 자료 출처를 달고, 없으면 추정값이라고 코드 주석과 이 문서에 적는다.

## 단계 (각 단계: UE Automation 통과 + 정규화 기준·단위와 함께 오차 기록)

### F0 근거 수집
- ASHRAE 액랭 수질/온도 등급(W17~W45), 공기 쪽 권장 흡기 범위(기존 18~27 °C).
- NVIDIA GB200 NVL72 랙 냉각수 요구(입구 온도·유량·차압), 공개 CDU 사양(인로우 1.35 MW급, 접근온도 등).
- 드라이쿨러 제조사 카탈로그(용량 대 외기·풍량, 팬 전력), 칠러 성능 곡선(DOE-2형 CAPFT/EIRFT/EIRFPLR 등 공개 형식).
- 결과물: 이 문서의 "근거 표"(값, 단위, 출처 URL, 공개/추정 구분). 근거 없는 수치는 넣지 않는다.

### F1 FWS 수력망과 구성 빌더
- CDU 1차측 ↔ 공급/회수 헤더 ↔ 설비 펌프(N+1) ↔ 드라이쿨러 코일. CDU 1차측 유량을 역산 고정값에서 **수력 해**로 바꾼다.
- 설비 망은 기존 `InRowLoopBuilder`처럼 **구성(분리/공용/직렬)을 입력으로 받는 빌더 하나**가 만든다. 이 단계에서는 분리만 채우고
  나머지 두 구성은 F3·F4에서 CHW가 생긴 뒤 F6에서 같은 빌더에 추가한다.
- CDU 1차측 2방 밸브(개도 → 저항)와 공급 차압 제어.
- 검증: 기존 수력 해석해 방식(직렬·병렬·펌프 운전점), 질량 보존, 밸브 개도 대 유량 단조성.

### F2 FWS 열과 드라이쿨러
- 배관·헤더 혼합 노드의 물 열용량(과도), 드라이쿨러 공기-물 ε-NTU(공기 쪽 풍량 = 팬 회전수비),
  팬 전력 운전점, 외기 건구온도 입력.
- 제어: FWS 공급 온도 설정점 → 드라이쿨러 팬 회전수(변화율 제한), 포화 시 "설정점 미달" 표시.
- CDU의 고정 `FacilitySupplyTempK`를 **계산된 공급 온도**로 대체(기존 고정 경계는 비교 기준 옵션으로 남김).
- 검증: ε-NTU 닫힌 해, 외기 → 랙 냉각수 → 칩까지 장부, 외기 상승 시 공급 온도·칩 온도 단조 상승(타당성).

### F3 CHW 루프와 칠러
- CRAH 코일 냉수 쪽 열용량률 유한(C_r > 0), CRAH별 2방 밸브로 토출 공기 온도 제어.
- 칠러: 용량 한계, 증발/응축 열수지, COP = f(부하율, 냉수 공급, 응축수 온도). 여러 대 단계 제어(N+1).
- CRAH의 고정 `CoilSupplyTempK`를 계산된 냉수 공급 온도로 대체(비교 기준 옵션 유지).
- 검증: `Q_cond = Q_evap + W` 항등, 용량 초과 시 냉수 온도 상승 → CRAH 제거열 감소 → 흡기 상승 연쇄.

### F4 응축 열 방출과 수측 이코노마이저
- CW 루프 + 드라이쿨러(기본). 판형 열교환기 이코노마이저(병렬/직렬 중 근거로 선택)와 전환 로직(외기 조건, 히스테리시스).
- 냉각탑은 습구온도 입력이 필요하므로 별도 선택 단계.

### F5 전역 장부와 시설 PUE
- 전역 열수지 경계를 **외기**까지 넓힌다: 입력 = IT + 모든 팬 + 펌프 + 압축기 일, 유출 = 드라이쿨러(·냉각탑) 방출, 축적 = 랙·냉각수·공기·설비 물.
- 펌프 축동력이 유체에 들어가는 열(기존 부채)을 넣는다.
- 냉각 PUE = (IT + 냉각 전체 전력) / IT. UPS·배전·조명은 모델에 없으면 "시설 PUE"라고 부르지 않는다.

### F6 구성 세 가지 시뮬레이션과 A/B 비교
- 빌더에 공용 냉수·직렬 구성을 넣는다(직렬은 혼합 노드와 3방 바이패스 밸브 포함).
- 선택: 콘솔 `vrg.Plant.Topology 0|1|2`(0 분리 기본), 통합 액터 속성, 저장 v2 선택 필드(없으면 분리).
  배치 모드에서 바꾸고 다음 시뮬레이션 진입 때 망을 다시 만든다(기존 컨테인먼트·CRAH 배치 전환과 같은 방식).
- 구성별 자동화 테스트 (`VRG.Plant.Topology.*`):
  - 공통: 질량 보존, 외기까지 전역 열수지(입력 = IT + 팬 + 펌프 + 압축기 일), `Q_cond = Q_evap + W`, D5 수렴/실패 표시.
  - 분리: CHW 설정점을 바꿔도 FWS 해가 **정확히 같다**(기존 "줄끼리 독립" 테스트와 같은 형식).
  - 공용: CDU 1차측 입구 온도 = CHW 공급 온도(같은 노드, 정확 일치). CDU·CRAH 분기 유량 합 = 공급 헤더 유량.
  - 직렬: CDU 1차측 입구 온도 = CRAH 회수 혼합 노드 온도(정확 일치). 바이패스 포함 유량 연속, 밸브 개도 대 혼합 온도 단조성.
  - 극한 사례: 외기가 충분히 차가우면(이코노마이저 운전) 압축기 일 0, 칠러 정지 시 냉수 온도 상승 → 흡기 상승 연쇄.
  - 타당성 안전망: 랙 냉각수 ΔT, 펌프·팬 전력/IT 비율, 흡기 범위 등 기존 안전망을 구성마다 건다.
- 비교 시나리오 (리포트·A/B, 기존 `vrg.Eval.Report/Compare` 확장):
  - 같은 배치·부하로 세 구성을 각각 실행, 외기 온도를 단계로 바꾸는 이벤트 프로파일(예: 차가운 날 → 설계 외기 → 더운 날).
  - 비교 항목: 냉각 PUE, 칠러 부하·압축기 전력, 드라이쿨러 팬·펌프 전력, 이코노마이저 운전 시간, CDU 2차측 공급 온도,
    칩 최고 온도, 랙 흡기(창 평균), 설정점 미달 시간.
  - 웹 대시보드 A/B 탭에 구성 이름과 설계점을 함께 표시해 같은 조건 비교인지 보이게 한다.
- 오차 기준은 `docs/오차기준.md`에 구성별로 정규화 기준·단위와 함께 기록한다.

### F7 표시·대시보드·이벤트
- 기계실/옥상 장비 액터와 설비 배관(계산 경로 그대로, 구성마다 다른 배관이 그려짐),
  웹 대시보드 냉각 설비 탭에 루프별 온도·유량·전력.
- 외기 시간 프로파일 이벤트(`vrg.Eval.Event`에 외기 추가), 장비 정지 이벤트는 S2b와 공유.

### F8 (팀 결정) 설비 장비 배치 편집·저장 v2
