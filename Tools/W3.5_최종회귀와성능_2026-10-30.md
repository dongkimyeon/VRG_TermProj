## 확인 중인 실패 원인과 수정 범위

1. 표시 경로에 없는 내부 수력 노드까지 일반 표시 배관 끝점으로 셌다. 외부 노드만 세고 기존 높이 오차 기준은 유지한다.
2. 마지막 CDU 삭제 시 내부 망이 없는 라디에이터 경로로 복귀하는데도 내부162배관 수가 같다고 검사했다. 기존 외부 분기 보존과 내부 망 제거를 별도로 확인한다.
3. 고갈 후 scalar CoolantTempK는 이제 회수 보기이므로 전체 물 저장을 대표하지 않는다. 실제 트레이 물 저장 증가를 검사한다.
4. 누수 지점 이동 시 특정 랙이 반드시 경보여야 한다던 옛 가정은 새 해에서 유량비0.9953/0.9959로 문턱0.985를 넘지 않는다. 실제 비율→경보 집합 검사는 유지하고, 위치를 바꾸면 수력 영향 방향이 이동하는지 확인한다. 경보 문턱은 변경하지 않는다(D4).
5. 내부 망 수력 잔차에 절대 수온 약300K를 곱하던 CDU 혼합식이 미세한 유령 열을 만들어 기존1e-12 루프 장부 검사를 실패시켰다. 트레이 열 이류와 동일한 초기 수온 기준의 엔탈피 차로 혼합식을 표현한다. 질량이 닫히면 같은 식이며 물성/유량/솔버 허용치/검사 기준을 바꾸지 않는다. 초기 수온 차만으로는 잔차가 남아, 아래와 같이 실제 열 경계 연산자까지 일치시켰다.

## 성능 준비

기존 VrgPerf.Capture·CSV·최초30프레임 제외/예열 대기를 재사용한다. 수력/랙 열/물 구분과 시뮬레이션 진행률 확인을 위해 읽기 전용 CSV 필드·종료 시 물리 리포트만 보강 중이다.
CouplingMs는 바깥 전체, Air SolverMs 안에 PressureMs가 포함되며 새 세부 비용도 CouplingMs의 일부다. 더해서 중복 계상하지 않는다.
실제 렌더/1280×720/32랙/33210셀/dt0.02s·동일 카메라·각 별도 새 프로세스로 누수 없음/내부 누수를 비교할 예정이다.
초기 조건/예열·측정 시간/실제 RHI·실행 종류·누수 위치·크기를 확정해 결과와 함께 남긴다. NullRHI/RenderOffscreen을 렌더 FPS로 쓰지 않는다.
기존 화면 도구 접근 실패는 재시도하지 않는다. 빌드/회귀 재개 뒤 측정해야 하며 동시 실행 부하를 섞지 않는다.

## 회귀 수정 검증 체크포인트

- Editor 빌드72.44s(첫 수정),22.64s(경계 일치),45.14s(혼합 검사 대조) 모두 성공. 빌드 중 소스 변경 없음.
- 단순히 절대 수온 대신 초기 수온 차를 쓰는 것만으로는 누수 루프 잔차가 남았다. 최종 수정은 `InRackTransport.BoundaryWK`의 공급/회수 계수와 고정 수온 항으로 CDU/내부 라디에이터 혼합을 닫는다. 트레이가 실제로 쓰는 경계 열량과 같은 연산자다. 외부 공급 배관과 내부 공급 분기 합 사이의 유한 Newton 질량 잔차는 수력 검사에 그대로 남긴다. 장부에 잔차 열을 추가하거나 유량/허용치/물성을 변경하지 않았다. 내부 망이 없는 기존 단일 노드 경로는 유지한다.
