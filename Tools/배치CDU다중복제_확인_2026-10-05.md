# 다중 CDU 복제 직접 확인 (2026-10-05)

Editor 빌드 성공, 영향11종 Automation 성공(10 무경고+1 기존 가상 루프 경고 동반/실패0). 사용자가 다중 CDU 복제 직접 확인 결과 전부 정상이라고 보고했다(2026-10-05). 이전 도구 확인은 미검증 기록으로 유지하며 사용자 입력 확인과 구분한다. 네이티브 앱 직접 조작이 비활성이고 기존 geometry unavailable/조합 입력 제약이 해소됐다는 근거가 없어 같은 실패를 반복하지 않았다. 사용자 다중 CDU 삭제 정상 보고와 구분한다. 아래는 직접 확인 절차이며 시설 전체 정상상태/FPS 검증이 아니다. 그래픽 드라이버 안내가 나오면 아니오로 진행한다.

1. 새 L_Test를 배치 모드로 실행한다. 기존 CDU와 추가/복제로 만든 런타임 CDU를 준비한다. `vrg.Layout.Save cdu_group_before`로 시작 상태를 저장한다. 두 CDU를 Shift+클릭으로 선택하고 Ctrl+D를 누른다.
2. 미리보기 두 개가 함께 나타나고 원본 두 대는 유지돼야 한다. 각 원본의 상대 위치·높이·방향·크기와 설정을 보존해야 한다. 첫 선택 CDU를 기준으로5cm 스냅한다. 다중 미리보기 중 R은 변화가 없어야 하며 단일 CDU 복제에서는 기존 R 회전이 동작해야 한다.
3. Esc는 전체 취소한다. 다시 시작해 원본이나 다른 장비와 하나라도 겹치게 하면 미리보기들이 빨갛게 표시되고 클릭해도 생성하지 않아야 한다. 유효 위치는 주황색이다.
4. 유효 위치에서 클릭하면 두 대가 함께 추가되고 원본은 유지된다. 반복 클릭이 같은 복제를 다시 만들지 않아야 한다. Ctrl+Z는 복제 두 대를 함께 제거하고 Ctrl+Y는 같은 ID/설정/전체 변환의 두 대를 함께 복원해야 한다.
5. CDU와 랙/스파인을 섞어 선택하면 Ctrl+D를 거절해야 한다. 드래그·사각형 선택·추가/복제 중·패치 창·시뮬레이션에서도 새 복제를 시작하지 않아야 한다. 복제 미리보기 중 패치 창이나 시뮬레이션으로 전환하면 전체 취소돼야 한다.
6. 줄에 더 가까운 위치로 그룹을 복제해 기존 최근접 CDU 배정과 배관이 갱신되는지 확인한다. Undo/Redo는 원래/복제 CDU 배정으로 돌아가야 한다. CDU 수가 늘어났다는 이유만으로 랙 IT 전력이 늘거나 줄마다 펌프가 중복되면 안 된다. 담당하지 않는 CDU에 배관이 없을 수 있다.
7. 복제 확정 후 `vrg.Layout.Save cdu_group_after`를 실행한다. `vrg.Layout.Load cdu_group_before`→`vrg.Layout.Load cdu_group_after`→후 파일 반복 Load로 복제 두 대가 제거/복원되고 중복이 없어야 한다. Load 성공 뒤 Ctrl+Z/Y는 기록 없음으로 거절돼야 한다. 실행을 끝내고 새 L_Test에서 후 파일 Load를 반복해도 같은 목록이어야 한다. 레벨 에셋 저장은 하지 않는다.

중간 생성/제거/복원 실패·총1cm 복원 충돌·상태/스택 유지·현재 열 상태/시계 미복사·따뜻한 생성 실패의 상태 원복은 자동화 검사 범위다. 장애물을 이동하는 새 편집은 기록을 추가하고 Redo를 비우므로 이를 같은 복원 충돌 절차로 혼동하지 않는다. 원복 자체의 연쇄 실패/극단 자원 고갈은 검사하지 않았다.

화면 증거는 기존 Alt+Print Screen→클립보드 PNG 저장→이미지 확인 방식을 사용한다. 이번 작업에서 화면/실제 다중 입력/FPS는 확인하지 않았다. 펌프 손실의 냉각수/공기 열 분배는 기존 부채이며 확장하지 않았다.

보고 예시: `다중 CDU 복제 직접 확인 결과: [모두 정상]` 또는 실패 번호·실제 동작.
