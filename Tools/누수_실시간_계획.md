# 실시간 누수·물 확산·침수 영향 계획 (2026-10-23 설계, W1~W3 완료, W3.5 랙 안 누수 설계 2026-10-28)

사용자 요청(2026-10-23): 시뮬레이션 중에 누수를 실시간으로 낼 수 있어야 하고, 새어 나온 물이 수압에 따라 뿜어지고 바닥에 퍼지는 모습을 보여 주며,
물이 닿은 전자기기에 어떤 문제가 생기는지(트립·고장 등)를 실시간으로 알 수 있어야 한다. 이 문서는 **설계만** 담는다. 구현은 하지 않았다.

**단계 순서상 위치 (2026-10-23 사용자 결정):** ① S8(구현 끝) → ② 배치 모드 완전 검증(진행 중, 직접 확인 남음) → **③ 이 계획** → ④ 웹 대시보드(진짜 맨 마지막).
②의 완료 조건을 통과한 뒤 착수한다. 각 단계는 완료 조건을 통과하기 전에 다음으로 넘어가지 않는다.

**기준(2026-10-23 사용자): "물도 진짜 물이 흐르는 것처럼"** - 디지털 트윈이므로 새어 나온 물은 실제 물의 물리(관성·중력·마찰·표면장력·젖음 경계)로 계산하고,
그 계산 결과를 실제 물처럼(반사·굴절·흐름·물보라·젖은 표면) 보여 준다. 화면의 물은 계산한 물이며, 따로 도는 시각 효과용 유체 시뮬레이션(예: Niagara Fluids)을 쓰지 않는다
(보이는 것 = 계산하는 것). 근사가 필요한 곳은 근사라고 적고, 해석해·실험 자료와 대조한다.

지켜야 할 규칙: D4(영향 범위·고장 순서를 표로 정하지 않고 계산 결과로 판정), D2(유량 0에서 특이해지지 않게), D9(센서는 모의 계측값),
규약 1·2·4·5·6·7(SI 단위, K 저장, 하나의 SimTime, 워커는 액터 안 만짐, 한 번 계산해 양쪽에, SoA·핑퐁), "보이는 것 = 계산하는 것", 보존 검사 + 타당성 안전망, 추정값 표시.

## 0. 지금 상태 (2026-10-23)

### 된 것
- **방 냉각수(TCS) 누수, S2b:** 누수 오리피스 `Q = Cd·A·√(2Δp/ρ)`(역류 없음), 높이·정수압, 줄마다 팽창탱크·냉각수 재고·보충수, 누수 열 장부(전역 유출에 한 번),
  랙 분기 밸브 격리(격리 범위와 수력 영향 범위를 따로 판정, D4), 장애 판정(`VrgFaultMonitor`), 웹 대시보드 누수 레이어. 기록 `docs/기록/08_냉각수_누수.md`.
- **설비 세 루프 누수, S8 F6b:** FWS·CHW·CW의 노드 누수, 보충수(무제한, 15 °C 추정), 누수 열 장부, 영향 범위는 망 재풀이. 실행 중 추가 가능(`vrg.Plant.Fault leak …`, 이벤트 `plant`).
- **센서 누수 감지(2026-10-22~23):** 모든 그린 배관에 3 m 간격 계측 지점(`FInstrumentBank`). 덮는 구간에 흘러나온 물 0.5 L(추정)로 젖음, 경보 유지,
  로그·뷰포트 빨간 라벨·평가 리포트 표. 유량·수온 판독(D9).

### 안 된 것 (이 계획의 출발점)
1. **방 누수를 실행 중에 새로 낼 수 없다.** 누수를 넣을 때 배관을 둘로 나눠(`FHydraulicNetwork::SplitPipe`) 중간 노드를 만드는데, 그러면 배관 번호가 밀리고 결합은
   진입 때 번호를 쥐고 있어 어긋난다(CLAUDE.md "반복하지 말 것" 교훈). 그래서 `vrg.Leak.Add`는 진입 전에만, 실행 중에는 구멍 크기(`vrg.Leak.Size`)만 바꾼다.
2. **새어 나온 물이 어디로 가는지 계산하지 않는다.** 누수 유량은 망에서 빠져나가 장부에서 사라질 뿐, 분사·낙하·바닥 확산이 없다. 센서의 "덮는 반경"은 게임용 추상화다.
3. **물이 닿은 장비에 아무 일도 일어나지 않는다.** 침수·분사로 인한 전원 트립·고장·발열 소실·팬/펌프 정지가 없다.
4. **누수 경보 해제 명령이 없다**(실행이 끝날 때까지 유지, 재진입 시 초기화).
5. **감지 → 자동 밸브 격리 연동이 없다**(밸브는 사람이 `vrg.Valve`·이벤트로).
6. **누수·밸브 상태를 배치 저장 파일에 넣지 않는다.**
7. **웹 대시보드에 센서 경보가 없다**(기존 S2b 누수 레이어는 있음, 웹은 ③단계).
8. **알려진 모델 한계:** 재고 고갈은 "유량 0"까지만(2상·루프 열용량 감소 없음, 탱크 열용량 없음), 설비 보충수 무제한, 설비 누수 위치는 마당 도식 기준,
   감지 기준(0.5 L, 1 mL/s)·탱크·보충 기본값은 추정, 과열 문턱 85 °C 추정, 습도·결로 없음.

## 2. 설계

### L1. 실시간 누수 지점 (위상을 바꾸지 않는 방법)

**방식(권장): 잠재 누수 지점을 빌드 때 미리 만든다.** 방을 지을 때 후보 지점마다 배관을 나눠 중간 노드와 구멍 0의 누수 요소를 넣어 둔다.
실행 중 누수 = 그 요소의 구멍 크기를 바꾸는 것(`SetLeakHoleDiameterM`, 이미 있음)이라 배관 번호가 바뀌지 않는다. 구멍 0이면 유량 0이고 재고 풀이도 쉬어(`FCoolantInventory::IsActive`) 정상 운전 결과는 그대로다.

- 후보 지점: 모든 랙 분기 공급·회수 중간(지금 `AddLeak`이 나누는 자리), 헤더·CDU 연결관은 `vrg.Leak.SiteIntervalM`(기본 3 m, 계측 지점과 같은 간격) 마다.
  L_Test 기준 수십~백여 노드 증가 → 노드 200개를 넘는 줄은 이미 있는 Eigen SparseLU 경로(D3).
- 설비 세 루프: 이미 실행 중 누수가 된다(노드 누수). 메인·분기 배관 중간에도 같은 방식으로 잠재 지점을 둬, 아무 배관 지점에서 낼 수 있게 한다.
- 대안 B(위상 실시간 변경 + 결합 번호 재매핑)는 결합·센서·표시가 쥔 번호를 모두 다시 이어야 하고 앞의 교훈과 같은 부류의 위험이 있어 택하지 않는다.
- 누수 지점 선택: 시뮬레이션 모드에서 배관을 클릭(배관 메시·계측 지점 광선 판정) → 가장 가까운 잠재 지점. 키로 구멍 크기(예: 1·3·10·30 mm, 파단 = 배관 안지름) 선택, `Esc` 취소.
- 콘솔·이벤트: `vrg.Leak.At <x> <y> <z> <mm> [방향]`, `vrg.Leak.Repair <번호|all>`, 이벤트 `leakat`. 같은 지점 재선택은 크기 변경.
- 저장: 잠재 지점 간격만 저장(설정), 진행 중 누수는 실행 상태라 저장하지 않는다(필요하면 이벤트 목록으로 재현).

### L2. 분사 (구멍에서 나간 물)

- **원천:** 유량은 망의 누수 유량을 그대로 쓴다(한 번 계산, 규약 6). 분출 속도 `v0 = Cv·√(2·Δp/ρ)`, Δp = 구멍 위치 계기압(망 해, 정수압 포함),
  속도 계수 `Cv` 0.97(날카로운 구멍 교과서 값, 균열은 추정). 물줄기 지름은 연속식 `Q = v0·π·d²/4`로 정한다.
- **방향:** 누수마다 단위 벡터(시나리오 입력; 기본은 아래쪽 원뿔 안 씨앗 고정 무작위). 실제 균열 방향은 알 수 없으므로 추정이라고 표시.
- **물줄기(연속 구간):** 공기 항력(구형 액적보다 작은 원주 항력, 항력 계수 추정) + 중력으로 중심선 궤적 적분. 분열 거리 `L_b`(Weber·Ohnesorge 수 상관식,
  예: 고속 원형 제트의 L_b/d ≈ 수십~수백, 출처 확정 후 적용)까지는 하나의 물줄기.
- **액적(분열 뒤):** 질량을 나눠 가진 대표 액적(Lagrangian 입자, 크기 분포는 상관식, 수천 개 상한)을 항력·중력으로 추적. 입자는 계산 입자이며 표시도 같은 입자다.
- **충돌:** 장비 상자·벽·천장 판·바닥과 교차. 충돌 속도·각도로 튀김(Weber 수 문턱 위면 일부 질량이 2차 액적, 아래면 표면에 부착 - 문턱·분율은 상관식/추정).
- **표면 물막:** 장비·벽 수직면에 부착된 물은 중력 물막(Nusselt 박막 유량-두께 관계)으로 아래로 흘러 그 장비의 높이별(랙이면 슬롯별) 젖음을 남기고,
  바닥에 닿으면 L3 원천이 된다. 랙 앞·뒷문 틈으로 들어가는 분율은 추정(문 구조 모델 없음).
- **보존:** 공중의 물(물줄기 + 액적) + 표면 물막 + 바닥 물 + 장비 안 물 + 배수 = 누적 누수. 무차원 잔차를 측정해 기록.

### L3. 바닥 확산 (얕은 물 방정식)

- **방정식:** 2차원 얕은 물(Saint-Venant) 질량·운동량 보존 - 관성, 수면 기울기(중력), 바닥 마찰(Manning, 바닥 마감별 계수 추정), 바닥 경사(기본 수평, 입력 가능).
  "가상 파이프"·확산파 근사는 관성이 없어 물이 밀려가 부딪히고 되돌아오는 모습이 안 나오므로 쓰지 않는다.
- **수치:** 유한체적, 젖은/마른 경계를 다루는 잘-균형(well-balanced) 기법(예: Kurganov-Petrova 중앙-풍상 또는 HLL + 정수압 재구성; 음수 수심 없음).
  면 플럭스를 한 번 계산해 양쪽 셀에 부호만 바꿔 적용(규약 6), SoA·핑퐁(규약 7), CFL `Δt ≤ C·Δx/(|u|+√(g·h))` 서브스텝으로 통합 SimTime 한 스텝을 나눠 적분(규약 4).
- **표면장력·젖음:** 실제 물은 바닥에 끝없이 얇게 퍼지지 않는다. 접촉각에 따른 평형 웅덩이 두께 `h_eq = 2·l_c·sin(θ/2)`(모세관 길이 `l_c = √(σ/(ρg))` ≈ 2.7 mm,
  에폭시·타일 바닥 접촉각은 추정)보다 얇은 앞부분은 멈추게 하는 전진 조건(접촉선 고정)을 둔다. 이 두께가 장비가 젖느냐를 가른다.
- **격자:** 방 바닥 균일 격자(기본 2.5 cm, `vrg.Water.CellM`), 물이 있거나 이웃한 셀만 활성(희소 활성 집합). 13.5 × 10.3 m 기준 약 22만 셀 → GPU 계산 셰이더 경로
  (기존 GPU FP64 공기 경로처럼 결과 동일성은 CPU 기준 경로와 허용 오차로 대조). CPU 경로는 검증 기준.
- **장애물·발판:** 벽·차단막·방 경계는 불투과. 랙·CDU·CRAH·스파인 발판은 장비 바닥 간극(다리·바퀴·받침대 높이, 추정)만큼 물이 밑으로 흐르는 셀이며,
  그 셀의 수심이 장비의 침수 깊이다(L4). 케이블 트레이·배관 받침 기둥은 무시(한계).
- **배수:** 배수구 위치·용량(추정, 기본 없음).
- **열:** 새어 나간 물의 열은 이미 냉각수 장부에서 유출로 처리. 바닥 물-공기 열교환·증발 잠열은 없음(습도 모델 없음, 한계).
- **검증(완료 조건):** 부피 보존 잔차, 정지 웅덩이(수면 수평·유속 0 유지, well-balanced), 마른 바닥 댐 붕괴의 Ritter 해석해 대조(앞부분 속도 `2√(g·h0)`),
  젖은 바닥 댐 붕괴의 Stoker 해석해 대조, 평형 웅덩이 두께, 격자 수렴(2.5 / 5 cm), CPU·GPU 허용 오차 대조, 결정성.

### L3.5. 랙 안 누수 (2026-10-28 사용자 결정, W3 뒤·W4 앞)

**왜:** W1~W3의 누수는 랙 밖 배관(랙 분기 공급·회수, 공급 헤더 티, 설비 루프)에서만 생긴다. 랙은 수력에서 배관 하나, 열에서 냉각수 노드 하나
(`CoolantHeatCapacityJK` 9.2e4 J/K = 매니폴드 + 트레이 27개 물 약 22 kg)라 "랙 안 매니폴드·트레이 커넥터·냉각 플레이트에서 샌다"를 표현할 수 없다.
W2는 장비 상자 안 구멍의 물을 바로 바닥으로 보내기만 한다(`ThroughEquipmentM3`). W4의 슬롯별 젖음·트립은 랙 안 물 경로가 있어야 뜻이 있다.

**L3.5-a 랙 안 수력망 (위상 고정, W1과 같은 원칙):**
- 방을 지을 때(줄 배관을 만들 때) 액랭 랙 하나의 분기 배관 자리를 랙 안 망으로 바꾼다:
  공급 분기 → 공급 매니폴드(세로, 트레이 높이마다 티 노드) → 트레이마다 [공급 커넥터·호스 → 냉각 플레이트 입구 → 냉각 플레이트 출구 → 회수 커넥터·호스] → 회수 매니폴드(티 노드) → 회수 분기.
  노드 높이는 슬롯 높이(`Gb200SlotZ0M`·`Gb200UnitM`·`LayoutU`)에서 가져와 기존 정수압(피에조 압력)에 그대로 들어간다.
- 잠재 누수 지점(닫힘, 구멍 0)을 트레이마다 5개 둔다: 공급 매니폴드 티, 공급 커넥터, 냉각 플레이트(입구·출구 사이 중간 노드), 회수 커넥터, 회수 매니폴드 티.
  랙당 27 × 5 = 135개. 실행 중 누수는 구멍 크기만 바꾼다(위상·배관 번호 불변, W1 교훈). 랙 밖 W1 지점 3개는 그대로 둔다.
- 저항 보정: 설계 유량에서 랙 안 망 전체의 압력 강하가 지금 랙 분기 저항의 압력 강하와 같도록 트레이 저항을 정한다.
  트레이별 설계 유량 몫은 트레이의 설계 냉각수 열(부품 `ToCoolantUAWK` 몫, `DesignHeatToCoolantW`와 같은 계산)에 비례(트레이마다 설계 ΔT가 같다는 추정).
  매니폴드 구간 저항은 공개 값이 없으면 추정(작게, 트레이 저항의 몇 %)이며 주석·문서에 표시한다. 매니폴드 손실 때문에 트레이 유량이 완전히 고르지는 않다(그게 계산 결과다).
- 유닛 탈착(`E`): 뽑힌 트레이는 커넥터가 닫히는(드라이 브레이크, 추정) 것으로 그 트레이 가지를 닫는다. 지금의 "꽂힌 액랭 슬롯 수로 분기 저항 비례"(`CountLiquidSlots`)를 대체하므로
  둘이 같은 경향을 내는지 대조한다.
- 규모: 32랙이면 노드 약 4300개 늘어남. 누수·보충이 없을 때는 지금처럼 정적 해 1회. 누수 중 스텝마다 재풀이는 희소 LU 비용을 측정해 기록한다.
  너무 무거우면(측정으로 판정) 랙 안 내부 노드를 정확히 소거(정적 축약 = 같은 방정식)하는 길을 쓴다. 근사(위상표·고정 비율)로 바꾸지 않는다(D4).
- 랙 안 배관은 계측 지점(`vrg.Sensors.PipeIntervalM`)·배관 메시·웹 3D 배관 목록에서 뺀다(수천 개가 되어 표시·웹이 깨지지 않게). 대신 열린 지점만 표시한다.
- 랙별 라디에이터 모드(CDU 없음, 가상 루프)·스파인 랙에는 랙 안 망을 만들지 않는다.

**L3.5-b 트레이별 냉각수 열:**
- 액랭 슬롯마다 냉각수 노드 하나(냉각 플레이트 물 + 호스 물), 매니폴드 물은 공급·회수 매니폴드 노드 각 하나(또는 매니폴드 몫을 랙 출구 혼합 노드 하나로, 구현 때 단순한 쪽).
  열용량 합은 지금 9.2e4 J/K를 유지하고 매니폴드/트레이 나눔 비율은 추정(예: 매니폴드·호스 40 %, 트레이 60 %를 유량 몫대로).
- 트레이 노드: `C_t dT_t/dt = Σ(그 트레이 부품의 Heat_to_coolant) − m_t·cp·(T_t − T_in,t)`. 부품의 냉각수 쪽 열은 자기 트레이 노드 온도로 계산한다(지금은 랙 노드 하나).
  랙 출구 = 트레이 출구의 유량 가중 혼합(회수 매니폴드 노드). 유량 0이면 실어 나가는 열 0 → 축적(D2, 나눗셈 없음).
- 결합: `FCouplingBridge`가 트레이 유량 배열(트레이 가지 배관 번호)을 랙 입력에 넣는다. 지금의 `CoolantMassFlowKgs`(랙 분기)는 "랙 분기 유량"으로 남겨 교차 확인에 쓴다.
  교차 확인(2026-10-28 사용자 승인 정정): 랙 공급 = 랙 회수 + 모든 내부 누수. 각 트레이는 입구 = 출구 + 트레이 누수,
  매니폴드는 티마다 유입 = 유출 + 티 누수를 각각 검사한다. 트레이 출구 합에 회수 매니폴드 누수를 다시 더하지 않는다.
- 누수 열 장부: 랙 안 지점의 누수 물은 그 지점의 물 온도로 한 번만 유출(공급 쪽 = 랙 입구 온도, 냉각 플레이트 = 그 트레이 노드 온도, 회수 쪽 = 트레이 출구·회수 매니폴드 온도). 규약 6.
- 안정성: 트레이 노드 열용량이 작아져 명시적 오일러 안정 한계가 줄어든다. 지금 냉각수 노드의 안정 검사(`RackThermalModel.cpp` 냉각수 시간 상수 검사)를 트레이 노드에도 걸고, 필요하면 지수 적분(정확 해)으로 바꾼다. 고정 횟수 반복 금지(D5).

**L3.5-c 랙 안 물 경로:**
- 새 계산 `Simulation/Water/RackInteriorWater`(SoA, 랙 × 슬롯 평탄 배열). 수력 장부가 적은 랙 안 누수량을 받는다(규약 6, W2가 랙 밖 누수량을 받는 것과 같은 길).
  랙 안 누수는 W2 물줄기를 만들지 않는다(랙 안은 막힌 공간이라 물줄기가 밖으로 나가지 않는다고 봄, 추정).
- 트레이·커넥터·냉각 플레이트 누수: 물이 그 슬롯에 들어가 슬롯마다 붙잡히는 물(보유량, 추정 예: 트레이당 수십 mL)을 채우고, 넘친 물은 아래 슬롯으로 내려간다(배수 시간 상수, 추정).
  공랭 슬롯(전원 셸프·관리 스위치)도 물이 지나가면 젖는다. 맨 아래 슬롯을 지난 물은 랙 바닥에서 W3 바닥 물로(랙 발판 셀, 앞뒤 위치는 지점에 따라).
- 매니폴드 누수: 랙 뒤쪽 매니폴드를 따라 흘러내린다. 아래 슬롯의 뒤쪽 커넥터 영역을 "뒤쪽 노출"로 기록(슬롯 안 보유량에는 일부만, 비율 추정)하고 랙 뒤쪽 바닥으로 나간다.
- 기록(W4 입력): 슬롯마다 현재 보유 물, 지나간 누적 물, 처음 젖은 시각, 뒤쪽 노출. 위쪽(누수 지점보다 높은) 슬롯은 젖지 않는다.
- 부피 장부: 누수량 = 슬롯 보유 + 이동 중 + 바닥 전달. 바닥 전달은 W3 부피 장부로 이어진다.
- 두 스텝 루프(`Tick`, `DrainWarmupSteps`) 모두에 연결한다(W2 교훈).

**L3.5-d 감지:**
- 랙마다 바닥 드립 트레이 센서(랙 바닥에 도착한 누적 물이 문턱을 넘으면, 문턱 추정 예: 수십 mL)와 뒤쪽 매니폴드 감지 로프(매니폴드를 따라 흐른 물이 닿으면).

**L3.5-e 조작·표시:**
- `L` 도구: 랙 앞면 조준 → 맞은 높이의 트레이 → 기본 지점 냉각 플레이트. 도구 안에서 지점 종류 순환(냉각 플레이트 → 공급 커넥터 → 회수 커넥터; 키는 구현 때 빈 키 확인).
  랙 뒷면 조준 → 그 높이의 공급·회수 매니폴드 티. 랙 안 구멍 크기 단계는 랙 밖보다 작게(예: 1 mm → 3 mm → 파단(호스 안지름) → 수리, 모두 추정·시나리오 입력).
- 콘솔: `vrg.Leak.Sites`에 랙 필터(예: `vrg.Leak.Sites rack 3`, 수천 개 전부를 찍지 않음), `vrg.Leak.At`·`vrg.Leak.Repair`와 이벤트 `leakat`이 랙 안 지점 이름(예: `랙 3 트레이 C07 냉각 플레이트`)을 받는다.
- 표시(디버그 수준, 실제 물 표시는 W6): 열린 지점 표식, 젖은 슬롯 앞면 테두리, 드립 트레이 물량 라벨. 계측 라벨에 트레이 냉각수 온도·유량(조준한 랙만).

**L3.5-f 근거 (W3.5 착수 첫 일):** GB200 NVL72 공개 자료(NVIDIA·OCP·제조사 매니폴드·UQD 사양)에서 랙·트레이 유량, 매니폴드·커넥터 압력 강하, 호스 지름, 물 체적을 찾는다.
찾은 값은 출처를 달고, 못 찾은 값은 "추정"으로 주석·문서에 남긴다(지금 랙 설계 유량·분기 저항과 모순되면 먼저 보고).

### L4. 침수·분사 영향 (전자기기)

**원칙(D4):** "누수 → 랙 N대 고장" 같은 표를 쓰지 않는다. 장비마다 **물에 닿은 양**을 계산(L2 분사 노출, L3 침수 깊이)하고, 장비·부품별 문턱과 시간으로 상태를 바꾼다.
문턱은 모두 **추정값**(공개 근거를 찾으면 교체)이며 문서·주석에 표시한다.

- 노출량: 장비(랙은 슬롯별) 단위로 ① 침수 깊이 `h_flood`(발판 셀 평균 물 높이 − 장비 바닥 간극)와 슬롯 아래 끝 높이 비교, ② 분사 노출 유량·누적량, ③ 장비 안으로 들어간 물 부피.
- 상태 기계(장비·슬롯마다): `정상 → 젖음(경고) → 트립(전원 차단, 보호 동작) → 손상(복구 불가)`.
  - 젖음: 노출이 시작됨. 표시·센서만.
  - 트립: 통전 부품이 물에 닿은 상태가 지속 시간 문턱(예: 수 초, 추정)을 넘음 → 그 장비의 전원이 끊김.
  - 손상: 트립 상태에서 계속 젖어 있거나 누적 물량이 문턱을 넘음 → 수리 전까지 복구 불가(실행 중 복구 명령은 별도).
  - 냉각수 종류: TCS 냉각수(PG25 등 글리콜 혼합, 억제제 포함 → 전도성), 설비수(FWS·CHW·CW) - 모두 전도성으로 보고 같은 규칙(추정).
- 결과(기존 모델로 연결, 하드코딩 순서 없음):
  - 랙 슬롯 트립: 그 슬롯 발열 0·팬 정지(기존 유닛 탈착과 같은 경로) → IT 부하·공기 흐름·열이 계산으로 바뀜. 전원 셸프 트립이면 그 셸프가 공급하는 슬롯들이 함께 꺼짐(셸프-슬롯 대응은 프리셋 정보, 추정).
  - CDU 트립: 펌프 정지 → 그 줄 냉각수 유량 0 → 칩 온도 상승(기존 열 모델, D2) → 과열 판정(기존 85 °C 추정 문턱).
  - CRAH 트립: 팬·코일 정지 → 방 공기 온도 상승(공기 솔버).
  - 스파인 스위치 트립: 네트워크 장비 정지(발열 0). 연결된 랙의 "서비스 중단"은 표시만(IT 작업 모델 없음).
  - 설비 마당 장비(실외형 드라이쿨러·칠러·펌프): 실외 등급(IP54~55 수준, 추정)이라 누수 물에 트립하지 않음. 펌프 모터 침수는 깊이 문턱으로 트립(추정).
- 보고: 사건 로그(`t=…: 랙 3 슬롯 2(전원 셸프) 침수 3 mm → 트립, IT −14.6 kW`), 리포트 표, 장애 판정(`VrgFaultMonitor`)에 침수 원인 추가.

### L5. 감지·대응 개선

- 누수 감지 케이블을 L3 바닥 물 높이로 판정(케이블 위치의 물 높이 > 0.5 mm 추정)하도록 바꾼다 → "덮는 반경" 추상화 제거, 보이는 물 = 감지하는 물.
- 경보 해제 `vrg.Sensors.ResetLeak <번호|all>`(물이 남아 있으면 다시 울림).
- 자동 격리(선택, 기본 끔 `vrg.Leak.AutoIsolate 1`): 경보가 난 구간을 포함하는 랙 분기 밸브·설비 분기 밸브를 닫는다. 격리 범위와 수력 영향 범위는 따로 판정(D4, 기존 밸브 보고서).

### L6. 표시 (계산한 물을 실제 물처럼)

- **바닥 수면:** L3의 수심·유속 격자를 GPU에서 바로 높이 메시로 올린다(계산 버퍼를 렌더가 읽음, 수 프레임 지연 허용). 반투명 물 재질 - 프레넬 반사, 굴절(바닥이 비쳐 보임),
  수심에 따른 흡수 색, 유속장을 따라 흘러가는 노멀(flow map), 앞부분 젖음 경계. 높이는 과장하지 않는다(얇은 물은 얇게; 필요하면 표시 배율을 명시적 옵션으로만).
- **물줄기·액적:** L2의 물줄기 중심선을 지름만큼의 반투명 튜브(굴절 재질)로, 액적은 계산 입자 그대로 인스턴스·스프라이트로. 충돌·튀김 지점에 물보라(계산된 2차 액적)와 거품 표시.
- **젖은 표면:** 바닥·장비 표면의 젖음 양(L2 물막·L3 수심 이력)으로 표면 색을 어둡게·광택을 높인다(재질 매개변수). 마르는 과정은 모델이 없으므로 젖은 채 유지(한계).
- **장비 상태:** 젖음·트립·손상을 테두리 색·HUD 라벨·사건 목록으로. 기존 계측 라벨 겹침 정리에서 침수 경고는 누수 경보 다음 우선순위.
- **확인:** 표시 물 부피 = 계산 물 부피(자동 검사), 화면 사실감은 사용자 직접 확인으로 판정(AI 화면 확인과 구분).

### W2 결과 (2026-10-26, 완료: 자동화 + AI 화면 확인)

## 6. 이 계획의 한계 (미리 적어 둠)

- 분사의 분열·액적·튀김은 상관식(실험식) 기반이며 3차원 자유수면 CFD가 아니다. 구멍 방향·크기는 시나리오 입력.
- 바닥은 2차원 얕은 물 방정식(수심 평균) - 수직 방향 유속 분포·쇄파는 없다. 이중 바닥·배수관망 없음. 장비 내부 물 흐름은 부피 저장소로만.
- 젖은 표면이 마르는 과정(증발)이 없다.
- 전자기기 영향은 장비·슬롯 단위 전원 차단까지. 단락 전류·차단기 협조·UPS·화재는 없다.
- 문턱·시간·장비 바닥 간극·실외 장비 등급은 추정. 실측·사례와 비교·보정한 적 없음.
- 물과 공기의 열교환·증발·습도 없음.
- 랙 안 물(W3.5)은 슬롯 저장소의 연쇄(보유량·배수 시간 상수)이지 트레이 안 기하·흐름 해석이 아니다. 랙 안 누수는 물줄기를 만들지 않는다고 본다.
  매니폴드·커넥터 저항, 트레이 물 체적, 보유량, 드립 트레이 문턱은 공개 근거를 찾기 전까지 추정.
