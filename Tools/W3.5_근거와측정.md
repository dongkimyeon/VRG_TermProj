## 사용자 승인된 보존식 정정

회수 매니폴드에서 새는 물은 이미 트레이 출구를 통과했다. 따라서 트레이 출구 합에 모든 내부 누수를 더하면
회수 매니폴드 누수를 두 번 센다. 2026-10-28 사용자 승인으로 다음을 각각 검사한다.

- 랙 공급 유량 = 랙 회수 유량 + 모든 내부 누수.
- 각 트레이 입구 유량 = 트레이 출구 유량 + 트레이 내부 누수.
- 공급/회수 매니폴드의 각 티: 유입 = 유출 + 해당 티 누수.

- 기존 추정30mL 보유/0.25s 배수/뒤 포획10%를 그대로 재사용했다. 새 물성·수치 보정은 없다. 위 슬롯은 건조, 누수 수리 뒤에는 새 입력 없이 보유/이동 중 물만 계속 이동한다. 트립/손상은 연결하지 않았다.
- 앞/뒤 바닥 도착 누적량에서 W3가 이미 받은 양을 뺀 델타만 AddWater로 전달하고, 성공할 때만 전달 완료를 기록한다. 격자 밖·막힌 곳·미구성 격자/잘못된 위치는 대기량을 유지하고 재시도한다. W3의 기존 벽 근처 열린 셀 탐색 정책은 그대로다.
- 출구는 랙 로컬 바닥 면 앞(+X)/뒤(−X) 중심이다. 실제 위치·회전·스케일을 액터 경계에서 world m로 변환한다. 임의 오프셋 없이 W3 바닥으로 수직 투영한다.
- 분사와 내부 도착분을 합친 뒤 W3를 같은 dt에 한 번 갱신한다. Tick/DrainWarmupSteps가 기존 공통 물 함수를 쓰며, W2가 꺼지거나 새 누수가 멈춰도 내부 이동·잔류 바닥 물 계산은 계속된다.
- 새 실행은 누적 입력 기준점·슬롯 상태·전달 완료/대기 장부·바닥을 모두 초기화한다. 감소한 입력 카운터를 새 물로 임의 해석하지 않는다. 잘못된 배치는 물 상태와 소비 기준점을 유지하며 미소비 입력이 상류 장부에 남는다.

### 장부/API
- GetRackInteriorCoupling().GetWater(): 슬롯별 HeldM3/TransitM3/GetRearTransitM3/PassedM3/FirstWetS/RearExposureM3와 앞/뒤 바닥 도착 누적량.
- GetFloorDeliveredM3(false/true): W3가 실제 받은 앞/뒤 누적 m³. PendingFloorM3(): 도착했지만 아직 W3가 받지 못한 m³. PendingInputM3(GetInternalLeakedM3()): 아직 내부 모델이 소비하지 못한 입력.
- GetRackWaterFloorPointsM(false/true): 실행 진입 때 계산한 앞/뒤 world m 출구. 새 표시/조작은 없다.
- 내부 입력 = 슬롯 보유 + 앞/뒤 이동 중 + W3 전달 완료 + 바닥 전달 대기 + 미소비 입력. 바닥 도착 누적량과 W3 저장량을 이 식에 다시 더하지 않는다.
- W3는 기존처럼 received = stored + clipped를 별도로 검사한다. 외부 W2 물량과 내부 W3 전달분은 서로 다른 출처이며 같은 물을 두 경로에 넣지 않는다.
