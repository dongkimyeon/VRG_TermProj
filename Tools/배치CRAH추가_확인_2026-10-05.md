# CRAH 단일 추가 직접 확인 (2026-10-05)

코드/자동화 결과는 CLAUDE.md 최신 CRAH 절을 따른다. 아래 실제 L_Test UI/FPS는 미검증이며 기존 입력 도구 실패를 반복하지 않았다.

1. 새 L_Test의 배치 모드에서 `vrg.Layout.Save crah_base`로 자동 배치를 먼저 저장한다. 기본 인로우 자동 쿨러는8대다.
2. `CRAH 쿨러 추가` 버튼을 누르고 바닥을 가리킨다. 확정 전에는 기존 자동 쿨러가 유지되고 실제 액터는 늘지 않아야 한다. 주황 미리보기5cm 이동·R90°·Esc 취소를 확인한다.
3. 랙/자동 쿨러와 겹치면 빨강 미리보기·클릭 거절. 빈 곳 클릭은 기존8대를 같은 위치의 실제 쿨러로 전환하고 새1대를 더해9대가 돼야 한다. 같은 클릭으로 중복 생성되면 안 된다.
4. Ctrl+Z 한 번은 자동8대로, Ctrl+Y 한 번은 실제9대로 복원한다. 새1대를 더 추가하면10대, 한 번 Undo하면9대여야 한다. 추가한 쿨러 이동/R과 Undo/Redo 후 참조도 확인한다.
5. 미리보기 중 패치 창 열기/시뮬레이션 전환은 취소돼야 한다. 배치 복귀 시 미리보기가 남지 않아야 한다.
6. 9대 상태에서 `vrg.Layout.Save crah_added` → `vrg.Layout.Load crah_base`는 자동8대 → `vrg.Layout.Load crah_added`는 실제9대. Load 반복 시 중복이 없어야 하고 Ctrl+Z/Y는 기록이 초기화돼야 한다. 새 실행에서 같은 Load로 개수/위치/방향을 확인한다.
7. 시뮬레이션으로 전환해 쿨러 수·냉각·풍량/팬 전력 표시를 확인한다. 쿨러가 랙 IT로 추가되면 안 된다. 새 기본 쿨러는 기존 설계 총풍량을 분담하므로 총풍량/팬 전력 증가를 기대하지 않는다.

인로우/벽면 자동 배치를 전환하며 새 쿨러는 기본 인로우형이다. 천장 코일 비교 모드는 추가를 거절한다. CRAH 삭제/복제·자동 쿨러 클릭만으로 전환은 이번 지원 범위가 아니다. Saved/Layouts의 JSON 저장이며 레벨 에셋/열 상태는 저장하지 않는다. 정상상태 냉각 용량/FPS는 별도 검증 대상이다.
