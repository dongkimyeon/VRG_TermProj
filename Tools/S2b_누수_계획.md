## 1. 높이차(정수압) 선택지

규모: 랙 높이 약 2.2 m에서 `ρ·g·Δz = 997 × 9.81 × 2.2 ≈ 21.5 kPa`.
CDU 기준 2.0e5 Pa 대비 약 11%이고, 누수량은 √Δp를 따르므로 누수 위치(바닥/랙 위)에 따라 누수량이 **약 5%** 달라진다.
닫힌 루프 순환에서는 정수압이 루프를 한 바퀴 돌면 상쇄돼 유량 해에 영향이 거의 없다.

| 선택지 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 넣지 않음 (권장 시작점)** | 노드 높이 없이 압력만 쓴다. 펌프 정지 시 잔압은 팽창탱크 압력으로만 표현 | 솔버·기존 테스트 변경 없음 | 누수 위치에 따른 약 5% 차이, 펌프 정지 뒤 높은 곳의 사이펀·낮은 곳의 잔류 누수를 못 본다 |
| B. 노드 높이 + 정수압 항 | 노드에 `ElevationM`, 배관 식을 `P_from − P_to + ρ·g·(z_from − z_to) = R·Q·|Q|`로 | 물리적으로 일관, 펌프 정지 후 잔류 누수까지 계산 | Jacobian·기존 해석해 테스트 재검증 필요, 배관 메시 경로의 높이를 노드에 매핑해야 함 |
| C. 누수점에만 정수압 보정 | 누수 구동압에만 `ρ·g·(z_ref − z_leak)` 추가 | 작음 | 망 해와 누수식이 서로 다른 압력장을 보게 돼 **비일관**. 권장하지 않음 |

권장: **A로 1~5단계를 끝내고, B는 선택 단계(2b)로 둔다.** 팀이 "펌프 정지 뒤 잔류 누수"를 시연하고 싶다면 B를 3단계 전에 넣는다. C는 쓰지 않는다.

**결정 (2026-10-20, 팀): 선택지 B를 쓴다. 순서를 바꿔 높이 단계(옛 2b)를 1단계(누수) 앞에 한다.**
높이가 누수 구동압에 바로 들어가므로, 누수를 먼저 만들면 누수 테스트를 높이 추가 뒤 다시 검증해야 하기 때문이다.
새 순서: 높이(구 2b) → 1 누수 → 2 재고·팽창탱크 → 3 열 장부 → 4 밸브 → 5 장애 판정 → 6 웹. 높이 단계 결과는 맨 아래 "높이 단계 결과" 절.

## 2. 단계 (작은 커밋 단위)

각 단계는 "영향 테스트만, 문서 적고 커밋"으로 진행한다. 오차 기준은 **측정해서 정하며**(검증 규칙),
아래 "기준 후보"는 기존 수력·열수지 기준과 같은 수준에서 출발하는 값이다. 측정 뒤 CLAUDE.md 오차 기준표에 정규화 기준·단위와 함께 적는다.

### 1단계 — 누수 오리피스 (수력만)

- 압력 정의: **모든 수력 압력은 계기압 [Pa(g)], 대기 = 0**으로 문서화한다. 기존 결과는 압력 차만 쓰므로 바뀌지 않는다.
- 누수 요소: 기존 노드(또는 배관을 둘로 나눈 중간 노드)에서 대기 고정 노드(0 Pa(g))로 가는 저항 `R_leak = ρ/(2·Cd²·A²)`.
  입력은 구멍 지름 [m]과 `Cd`. `Cd`는 날카로운 오리피스의 교과서 대표값(약 0.6)을 쓰되 **추정값**이라 주석에 적는다.
  역류(대기 → 망)는 막는다(누수 노드 압력 ≤ 0이면 누수 0).
- 누수 위치 단위: 1단계는 **랙 분기 공급/회수관과 CDU 공급·회수 헤더**로 한정(온도가 정의된 곳, 3단계와 맞춤).
- 이 단계에서는 CDU 고정 노드가 무한 저장소이므로 **"누수량 상한 확인용" 정적 해**만 낸다. 시뮬레이션에 켜는 것은 2단계부터.

| 완료 조건 (테스트) | 정규화·기준 후보 |
|---|---|
| 해석해: 고정 압력원 P_s – 배관 R₁ – 누수 R_L. `Q = √(P_s/(R₁+R_L))` | 누수 유량 상대 오차, 해석해 Q 기준 무차원 < 1e-9 (수렴 목표 1e-10의 한 자릿수 위, 기존 `SinglePipeAnalytic`과 같은 근거) |
| √Δp 스케일: P_s를 4배로 하면 Q가 정확히 2배 | 비율 상대 오차 < 1e-9 |
| 인로우 한 줄(NVL72 8랙) + 분기 누수: 질량 보존 | `|Σ유입 − Σ유출 − Q_leak|` / 펌프 유량, 무차원 < 1e-9 (기존 `Network.MassConservation`) |
| 구멍 지름 0 → 누수 없는 해와 같음 | 모든 유량 상대 차 == 0 또는 < 1e-15 |
| 역류 차단: 누수 노드가 대기압 이하면 누수 0 | 정확히 0 |
| 타당성 안전망: 분기 누수 1 mm·3 mm·10 mm에서 누수/펌프 유량 비가 단조 증가, 10 mm에서 펌프 유량을 넘지 않음 | 상식 범위 검사(물리 법칙 아님) |

### 2단계 — 냉각수 재고·팽창탱크·충전 압력·보충수 (시간 적분)

- 줄마다 CDU 기준 노드를 **팽창탱크**로 바꾼다: 고정 압력 노드이되 압력이 재고로 정해진다.
  기체 쿠션 등온 이상기체: `P_abs = P0_abs · V_gas0 / V_gas`, `V_gas = V_gas0 + (V_loop0 − V_water)`.
  계기압으로 넘길 때 대기압 101325 Pa를 뺀다(계산 단위 Pa, 규약 1).
- 재고 적분(규약 4, 통합 시계): `dV_water/dt = −Q_leak + Q_makeup`. 명시적 오일러로 스텝마다.
  **누수나 밸브 변경이 있는 동안에만** 스텝마다 수력망을 다시 푼다(준정상). 없으면 지금처럼 재구축 때 한 번 — 기존 결과와 비트 동일해야 한다.
- 보충수: 선택. 탱크 압력이 설정값 아래로 떨어지면 일정 유량(상한)으로 채운다.
- 재고 고갈: 탱크 물이 0이 되면(기체가 루프로 들어감) **"재고 고갈"** 상태를 결과에 표시하고 그 줄 펌프 유량을 0으로 둔다(D2: 유량 0에서 특이 계산 없음).
  고갈 뒤 기액 2상 거동은 모델에 없다고 문서에 적는다.
- 기본값(루프 물 부피, 탱크 부피, 사전 충전 압력, 보충수 설정)은 이 단계에서 공개 자료를 찾아 출처와 함께 정하고, 없으면 **추정값**이라 표시한다.
- 비용: 스텝마다 수력 재해석 비용을 측정해 기록한다(D10, 보장값 아님). L_Test 규모(줄 4개)는 D3 밀행렬 범위 안이다.

| 완료 조건 (테스트) | 정규화·기준 후보 |
|---|---|
| 부피 보존: `V_water0 − V_water − ∫Q_leak dt + ∫Q_makeup dt = 0` | 누적 누수 부피 [m³] 기준 무차원 < 1e-12 (열수지 장부와 같은 "장부" 성격) |
| 탱크 등온식: 임의 재고에서 `P·V_gas` 일정 | 초기 `P0·V_gas0` 기준 무차원 < 1e-12 |
| 시간 정밀화: dt와 dt/2에서 누적 누수량 오차 비율 ≈ 2 (1차 오일러) | 비율 1.9~2.1 (S5-C `CoolingAnalyticTimeRefinement`와 같은 방식), 기준해는 더 작은 dt 또는 닫힌 해 |
| 압력이 떨어지면 누수량이 단조 감소(고정 누수량 모델이 아님을 확인) | 단조성 |
| 누수 없음 → 기존 인로우·결합 테스트 결과 비트 동일, 수력 재해석 0회 | == 0 |
| 재고 고갈 표시·펌프 0·음수 부피 없음 | 논리 조건 |
| 규약 4: 수력 재해석 시각이 통합 시계 스텝과 일치, 남는 시간 버림 없음 | 기존 `SimClock.NoTimeLost` 수준 < 1e-9 s |

### 2b단계 — 노드 높이와 정수압 (B 결정으로 1단계 앞에서 완료, 결과는 맨 아래)

선택지 B를 택했을 때만. 노드 `ElevationM`(배관 메시 경로 높이에서), 배관 식에 `ρ·g·Δz`.
완료 조건: 수직 관 정지 유체 해석해(유량 0, `ΔP = ρ·g·Δz`) 상대 < 1e-12, 닫힌 루프 순환 유량이 높이 추가 전후 상대 < 1e-9로 같음,
기존 해석해 수력 테스트 전부 재통과, 바닥 누수 대 랙 위 누수의 유량 차가 `√(1 + ρgΔz/Δp)` 해석값과 상대 < 1e-9.

### 3단계 — 열 결합과 전역 장부

- 루프가 가득 찬 동안(재고 > 0)은 탱크가 새는 만큼을 즉시 공급한다고 본다. 루프 물 질량·노드 열용량은 그대로.
  누수로 나간 물은 누수점 온도 `T_leak`, 탱크에서 들어온 물은 탱크 온도 `T_tank`(CDU 공급 쪽).
  **전역 장부 유출 항에 `ṁ_leak·cp·(T_leak − T_tank)`를 한 번만** 더한다(규약 6: 수력이 정한 누수 질량유량을 열 쪽이 다시 계산하지 않음).
- `T_leak`: 랙 분기 공급 = 랙 입구 온도, 회수 = 랙 출구 온도, CDU 헤더 = CDU 공급/회수 온도(이미 계산됨). 헤더 중간점의 관별 온도는 모델에 없으므로 그 줄의 대표값을 쓴다고 명시.
- 누수로 랙 분기 유량이 줄면 기존 열모델이 온도 상승을 계산한다(D2). 과열 순서·시간을 하드코딩하지 않는다(D4).
- 재고 고갈 후 루프가 비면 열용량이 줄지만 이 단계에서는 "고갈 = 냉각수 유량 0"까지만 다룬다(한계로 기록).

| 완료 조건 (테스트) | 정규화·기준 후보 |
|---|---|
| 누수 포함 전역 열수지 `(입력 − 유출 − 축적)/누적 입력` | 기존 기준 < 1e-9, 무차원 |
| 누수 열 항 = `ṁ·cp·(T_leak − T_tank)` 직접 계산과 일치 | 누수 열 [W] 기준 상대 < 1e-12 |
| 누수 0 → 기존 결합 테스트 비트 동일 | == 0 |
| 냉각수 루프 장부(랙 반출 = 방출 + 누수 열) | 방출+누수 열 [W] 기준 상대 < 1e-12 (기존 `CoolantLoopClosesExactly`와 같은 성격) |
| 타당성: 누수가 큰 줄의 랙 냉각수 출구 온도가 올라가고, 다른 줄은 변하지 않음(줄끼리 독립, 기존 수력 결과) | 다른 줄 유량 상대 차 < 1e-9 |
| 공기·수력·압력 수렴, 덕트 거절 없음 | 기존 기준 |

### 4단계 — 밸브 격리

- 밸브 = 배관 위 개폐 요소. 닫힘은 기존 "분기를 아예 만들지 않는" 방식(저항을 큰 값으로 두지 않음)으로 망을 다시 만들고 다시 푼다.
- 두 범위를 **따로** 계산하고 표시한다(D4):
  - 격리 범위: 닫은 밸브로 망에서 위상적으로 끊긴 요소(그래프 연결성).
  - 수력 영향 범위: 재계산 전후 유량 변화가 문턱 이상인 랙. 문턱은 표시용 값이며 결과 자체는 전후 유량을 그대로 낸다.
- 밸브 조작은 통합 시계 이벤트로(`vrg.Eval.Event <t> valve <id> close|open`, 규약 4).

| 완료 조건 (테스트) | 정규화·기준 후보 |
|---|---|
| 누수 상류 분기 밸브를 닫으면 누수 유량이 정확히 0 | == 0 |
| 닫힌 뒤 해 = 그 분기를 처음부터 뺀 망의 해 | 각 분기 유량 상대 < 1e-9 (기존 `Network.SledUndockRedistributesFlow`와 같은 근거) |
| 격리 범위와 수력 영향 범위가 서로 다른 사례(분기 하나 격리 → 같은 줄 다른 랙 유량도 변함) | 논리 조건 + 유량 상대 차 보고 |
| 다시 열면 닫기 전 해로 복귀 | 상대 < 1e-9 |
| 재고·열 장부가 밸브 조작을 가로질러 닫힘 | 2·3단계 기준 |

### 5단계 — 장애 판정·이벤트·리포트

- 판정은 **계산 결과로만** 한다: 랙 냉각수 유량이 설계 대비 비율 아래, 부품 온도가 허용 온도 위, 재고 고갈, 압력 수렴 실패.
  부품 허용 온도는 모델에 없으므로 공개 자료(예: 칩 Tj 최대)를 찾아 출처와 함께 넣고, 없으면 **추정값**이라 표시한다.
  유량 비율 문턱은 판정 표시용 설정이며 물리 상수가 아니다.
- 이벤트: `vrg.Eval.Event <t> leak <위치> <지름 m>`, `valve <id> close|open`. 진입마다 다시 적용(기존 S6 방식).
- 리포트: 누수 시작 시각, 누적 누수 부피, 재고·탱크 압력 이력, 첫 장애 판정 시각(랙·종류), 격리 범위·영향 범위. 기존 리포트에 선택 필드로 추가(옛 리포트 호환).

| 완료 조건 (테스트) | 정규화·기준 후보 |
|---|---|
| 재실행 결정성: 같은 시드·이벤트 두 번 → 판정 시각·누적 누수 같음 | 수치 비교(기존 `Eval.RerunEventsAndReport`) |
| 판정이 하드코딩이 아님: 같은 누수를 다른 위치에 두면 판정된 랙 집합이 망 재계산 결과대로 바뀜 | 논리 조건 |
| 이벤트 시각에 정확히 적용(통합 시계) | 이벤트 시각 대비 스텝 이내 |
| 리포트 JSON 왕복·옛 리포트 읽기 | 정확 일치 |

### 6단계 — 웹 대시보드 (S2b 뒤)

누수 레이어(누수점·누수량·재고·격리/영향 범위), 냉각 설비·전력 탭 페이지(서버 `/api/cooling` 완료), 방 공기·센서·검증 탭, 패키징.

## 높이 단계 결과 (2026-10-20, 선택지 B)

**구현.**

## 1단계 결과 — 누수 오리피스 (2026-10-20)

**구현.**
- 압력 정의: 모든 수력 압력은 **계기압 Pa(g), 대기 = 0** (`HydraulicTypes.h` 머리, CDU `ReferencePressurePa` 주석). 기존 결과는 차만 썼으므로 불변.
- `FHydraulicLeak`(노드, 구멍 지름 m, `Cd`, 대기압 Pa(g)): `Flow = Cd·A·√(2(P − P_amb)/ρ)`, `P ≤ P_amb`이면 0(역류 없음).
  `R_leak = ρ/(2(Cd·A)²)`로 배관과 같은 2차 꼴이라 Newton(D3) 그대로, Jacobian에만 배관과 같은 하한을 건다. 누수는 그 노드의 유출로 질량 보존에 들어간다.
  P는 구멍 위치의 **정압**이므로 높이 효과(높이 단계)는 정압에 이미 들어 있다.
- `Cd` 기본 0.61: 날카로운 오리피스 교과서 대표값. 실제 균열·이음부 틈은 모양이 달라 **추정값**이다(주석에 범위 약 0.6~1).
- `FHydraulicNetwork::SplitPipe(배관, 비율, 높이)`: 배관 중간에 노드를 넣는다(저항을 비율로 나눔, 2차 손실 직렬 합이라 유량 불변). 배관 위 누수 위치용.
- 방 액터·시뮬레이션에는 아직 연결하지 않았다(계획대로 정적 해만). CDU 고정 노드가 무한 저장소라 누수 시 펌프 유량이 오히려 늘어난다(측정 아래 표) — 2단계 재고·팽창탱크가 바로 이 점을 고친다.

**검증 (NullRHI).** 신규 2건 + 영향 25건 = **27건 성공, 경고 0, 실패 0**

## 2단계 결과 — 팽창탱크·재고·보충수 (2026-10-20)

**구현.** `Simulation/Hydraulics/CoolantInventory.h/.cpp`.
- 줄마다 CDU 기준 노드(고정 압력)가 팽창탱크다. 압력은 탱크 물 부피로 정한다. 기체 쿠션 등온: `P_abs·V_gas = P_pre_abs·V_tank`, `V_gas = V_tank − V_water`.
  초기 물 `V_tank(1 − P_pre_abs/P_fill_abs)`. 충전 압력은 지금 CDU 기준 압력(2.0e5 Pa(g))이다.
- **루프 물 부피는 쓰지 않는다.** 물을 비압축·관을 강체로 보면 루프 압력을 정하는 것은 탱크 기체 쿠션뿐이고, 새어 나간 물은 전부 탱크에서 빠진다. 열 지연을 넣는 3단계 이후에 필요해지면 그때 정한다.
- 재고 적분은 통합 시계 스텝마다 명시적 오일러(규약 4): `dV_water/dt = −Q_leak + Q_makeup`. 그 스텝의 탱크 압력으로 수력망을 먼저 풀고(준정상) 그 해의 누수량으로 재고를 줄인다.
  결합 다리는 같은 스텝에서 새 유량을 읽는다(`DataCenterSimulationActor`가 `Bridge.Step` 앞에서 `Room->StepCoolantInventory`).
- **누수가 열려 있거나 보충 중일 때만** 다시 푼다(`FCoolantInventory::IsActive`). 누수가 없으면 풀이 0회, 기존 결과 그대로다.
- 보충수(기본 끔): 탱크 압력이 충전 압력 아래일 때만, 상한 유량 안에서, 처음 물 부피까지만 채운다(충전 압력을 넘지 않는다).
- 재고 고갈: 물이 0이 되면 `bDepleted`, 그 줄 펌프 회전수 0, 그 줄 누수 닫음, 탱크 압력 0 Pa(g)로 한 번 더 풀고 쉰다. 기액 2상·공기 유입 거동은 모델에 없다.
- 새 시뮬레이션 진입 때(`RestartCoolantInventory`) 탱크를 다시 채우고 펌프 회전수·구멍 크기를 지은 값으로 되돌린다.
- 누수 지정: 배치 모드에서 콘솔 `vrg.Leak.Add <랙 번호(줄 순서)> <supply|return> <mm> [Cd]` → 그 랙 분기 중간을 `SplitPipe`로 나눠 구멍 노드를 만든다(방 재구축).
  공급 분기 누수면 랙은 구멍 **아래쪽** 반(랙 입구로 들어가는 쪽) 유량을 읽는다. `vrg.Leak.Size`(크기만 바로), `vrg.Leak.Clear`, `vrg.Leak.Status`.
  누수는 저장 파일에 들어가지 않는다(실행 중 시나리오). 진입 직후 방이 아직 랙을 못 찾았으면 명령이 먼저 방을 짓는다.

**기본값 (공개 자료를 찾지 못한 것은 추정).** `FExpansionTankParams`, CDU 액터 `ExpansionTank`.

|---|---|---|
| 탱크 부피 | 24 L | **추정.** CDU 팽창탱크 부피의 공개 사양을 찾지 못했다. 소형 밀폐 루프 팽창탱크 흔한 크기 |

## 3단계 결과 — 누수 열과 전역 장부 (2026-10-20)

**구현** (`Simulation/Coupling/CouplingBridge.*`, 물리 식 추가 없음 — 이미 있는 유량·온도로 장부만 맞춘다).
- 링크에 랙별 공급/회수 분기 누수 인덱스(`SupplyLeakIndices`/`ReturnLeakIndices`, 방 액터 `GetRackLeakIndices`). 다리가 수력 해의 누수 유량을 kg/s로 한 번 바꾼다(규약 6).
- 탱크 물 온도 `T_tank` = **직전 스텝의 루프 공급 온도**(탱크가 CDU 공급 쪽에 있다고 봄, 탱크 자체 열용량·혼합은 모델에 없다).
- CDU 열교환기는 펌프 유량을 본다: `C_hot = Σṁ_i + L_s`, `C_hot·T_mix = Σṁ_i·T_out,i − L_r·T_out + (L_s + L_r)·T_tank`.
  그러면 항등적으로 **랙이 냉각수에 준 열 = CDU 부하 + Σ L_r·cp·(T_out − T_tank) + L_s·cp·(T_supply − T_tank)** 이다.
  마지막 합이 누수 열이고 `CloseCoolantLoop`에서 **한 번만** 계산해 전역 장부 유출(`EnergyOutJ`)에 더한다.
  공급 분기 누수는 `T_leak` = 랙 입구 = 공급 온도라 거의 0이고, 회수 분기 누수가 뜨거운 물을 들고 나간다.
- CDU가 없는 줄(랙별 라디에이터)도 같은 장부를 랙 하나짜리 그룹으로 적용한다.
- 누수가 없으면 더해지는 항이 전부 +0.0이라 기존 결과와 비트 동일하다.
- 스냅샷: `CoolantLeakHeatW`, 루프 장부 `RackCoolantOutJ`/`CoolantRejectedJ`/`CoolantLeakHeatJ`, 랙별 누수 kg/s. 예열 끝 장부 로그에 "누수 열" 항을 넣었다.
- 재고 고갈 = 냉각수 유량 0까지만 다룬다: 고갈된 줄의 랙은 냉각수로 열을 못 내고 자기 열용량으로 데워진다(D2, 기존 랙 모델 그대로). 루프가 비어 열용량이 줄어드는 것은 모델에 없다.

## 4단계 결과 — 밸브 격리 (2026-10-20)

**구현.**
- 수력망: `FHydraulicPipe::bClosed`(`SetPipeClosed`). 닫힌 배관은 풀이에서 빠지고(큰 저항이 아님) 유량이 정확히 0이다.
