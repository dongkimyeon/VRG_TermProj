# 2026-09-27 계획과 인계: 배치/시뮬레이션 모드 → 난류 모델 → 격자 수렴 → GPU

사용자와 합의한 순서다. 단계마다 끝나면 이 문서의 "진행 상태"를 갱신하고 커밋·푸시한다.
토큰이 끊겨도 다음 담당자(사람이든 AI든)가 이 문서만 보고 이어갈 수 있게 쓴다.
규약·설계 결정(D1~D10)·측정된 오차 기준은 `CLAUDE.md`가 우선이다. 이 문서는 그 위의 작업 계획이다.

## 배경 (왜 이 순서인가)

- 사용자 목표: **배치 모드**에서는 물리 없이 랙·CDU·CRAH를 부드럽게 배치하고, **시뮬레이션 모드**에 들어가면
  물리 계산이 시작되어 실제로 냉각되는 것(열 흐름)이 눈에 보여야 한다.
- 서버 노드(부품)별 발열·UA·열용량 값은 사용자가 **실측해서 나중에 교체**한다. 지금 값은 그대로 둔다.
- 지금 공기 솔버는 **비점성**이다(점성·열확산 없음, 수치 확산이 대신한다). 이 상태로 격자를 촘촘히 하면 답이 수렴하지 않는다.
  난류 모델(와점성)이 들어가야 격자 세분이 정확도로 이어진다.
- GPU: 촘촘한 격자 + 시간 가속(방 온도는 분 단위로 변하므로 1배속은 거의 안 움직인다)에는 GPU가 필요할 가능성이 높다.
  **CUDA가 아니라 UE 컴퓨트 셰이더**로 한다: 시뮬레이션 모드는 매 프레임 결과를 그려야 해서 결과가 GPU 텍스처에 그대로 있는 쪽이
  맞고(CUDA는 매 프레임 D3D12 인터롭), 모든 GPU·패키징에서 돈다. 난류 모델은 GPU 전에 CPU FP64로 먼저 검증한다
  (GPU에서 처음 짜면 모델 오류와 GPU 코드 오류를 구분할 수 없다).
- 사용자 제안(CUDA 정밀 배치 솔버 + 실시간 근사 확산 프리뷰)은 평가 후 채택하지 않았다: 공기만 푸는 정밀 레이어는 결합(팬·열 분배·CDU·CRAH)을
  잃어 오히려 덜 정확하고, 확산 근사는 이류 지배인 데이터센터 공기에 틀린 그림을 주며, 파이프 근사 누수는 D4 위반이다(수력망 재계산은 1 ms라
  근사할 이유도 없다). "같은 물리 모델, 두 해상도/모드"로 간다.

## 단계

### 1. 배치 모드 / 시뮬레이션 모드 분리

목표: 배치 중에는 물리·무거운 재구축이 돌지 않고, 시뮬레이션 모드 진입 때 한 번에 구성하고 시작한다.
- 1a. 모드 상태(배치 / 시뮬레이션)와 전환 키. 게임 시작은 배치 모드. 시뮬레이션 진입 때: 격자 자동 맞춤 → 고체·덕트·CRAH·CDU 구성 →
  수력망 풀이 → 결합 재구축 → 시계 0에서 시작. 배치로 돌아가면 시계·물리 정지(상태는 버림, 다음 진입 때 새로 시작).
- 1b. 배치 모드에서 실행 중 배치: 바라보는 랙/CRAH/CDU 선택(기존 시선 선택 재사용) → 잡기/옮기기(바닥 평면, 격자 0.66 m 등 스냅) → 90° 회전 → 놓기.
  배관·케이블은 놓은 뒤 디바운스 재구축(이미 있음).
- 1c. HUD: 현재 모드, 키 안내. 배치 모드에서는 물리 HUD 숨김.
- 완료 조건: 자동화 테스트(모드 전환 시 결합이 새로 구성되고 배치 모드에서는 솔버 스텝 0, 옮긴 랙이 다음 진입에서 격자·결합에 반영),
  L_Test 실행 확인, 전체 Automation 통과.

### 2. 난류 모델 (CPU FP64 먼저)

- 모델: **Chen & Xu (1998) 실내 기류용 0-방정식 모델** ν_t = 0.03874 · |V| · l (l = 가장 가까운 벽·고체까지 거리).
  출처: Q. Chen, W. Xu, "A zero-equation turbulence model for indoor airflow simulation", Energy and Buildings 28 (1998) 137–144.
  계수 0.03874는 논문 값이다. 유효 점성 = 공기 분자 점성 + ν_t, 열확산 = 분자 + ν_t / Pr_t (Pr_t = 0.9, 일반적 가정).
- 구현: 벽 거리장(고체·벽 기준, 토폴로지 바뀔 때만 계산), 셀별 ν_t, 운동량 확산(면 속도), 온도 확산(면 플럭스 한 번 계산 → 규약 6, 보존 유지).
  명시적이면 안정 조건 dt ≤ h²/(6 ν_eff) → 부분 스텝. 켜고 끄는 스위치(끄면 지금과 비트 동일).
- 검증: (a) 이산 라플라시안 고유모드(코사인) 확산의 정확한 감쇠율(균일 ν), (b) 닫힌 상자 열 보존(확산 켬), (c) 벽 거리장 해석값,
  (d) 타당성: L_Test 방 규모에서 ν_t 범위(대략 1e-3~1e-1 m²/s 예상, 측정 후 기록).
- 완료 조건: 테스트 통과 + 오차 기준을 CLAUDE.md 표에 기록.

### 3. 격자 수렴 검사

- 같은 구성(L_Test 또는 축소 방)을 h = 0.25 / 0.125 m(가능하면 0.0833)로, 난류 모델 켜고, 정상 상태 근처까지.
- 지표: 랙별 시간 평균 흡기 온도, 최고 흡기 위치·값, CRAH 제거열, 전역 잔차. 난류 끔 대비도 함께.
- 결과로 결정: 0.25 m로 충분(차이 작음) → GPU는 시간 가속·방 확장용 / 차이 큼 → 4단계로 촘촘한 격자 실시간화.

### 4. GPU 컴퓨트 셰이더 이전

- 속도 이류·부력·난류 확산·온도 수송·투영(다중격자 또는 PCG)을 HLSL 컴퓨트 셰이더로. 필드 FP32, 에너지 장부는 FP64로 따로 누적.
- CPU FP64 경로는 **기준·폴백으로 남긴다**. 비교 테스트는 허용 오차로. GPU 경로용 오차 기준을 새로 측정해 기록(기준 변경은 팀 합의 사항).
- 볼륨 렌더링이 GPU 필드를 복사 없이 읽게 연결. 시간 가속 배율(×1/×5/×10) 선택.

#### 4단계 세부 계획 (2026-09-27, 착수 시 기록)

기준선(3단계 측정, CPU 16코어, 0.125 m 265680셀 32랙 L_Test): 공기 스텝 약 50 ms = 투영 32 + 난류 6.9 + 속도 이류 4.4
+ 온도 수송 4.4 + 벽·덕트 1.3 + 부력 0.9. 목표는 **통합 스텝 20 ms 안**(S7-5 절벽).

위 계획에서 두 가지를 바꾼다(이유를 남긴다).
- **필드도 FP64로 GPU에 둔다(위의 "필드 FP32"를 바꿈).** 300 K 근처 온도를 FP32로 두면 분해능이 약 3e-5 K라 스텝당 작은 온도 변화가
  잘려 **보존 자체가** 깨진다(장부만의 문제가 아니다). 커널은 전부 메모리 대역폭 제한(격자 한 번 훑기에 수십 MB, RTX 4080 717 GB/s)이라
  FP64 연산이 1/64이어도 셀당 연산이 적어 비용은 대역폭 2배 수준으로 예상한다. 먼저 UE 셰이더 파이프라인이 `double`을 받는지 확인하고,
  안 되면 FP32로 돌아가고 그 사실과 오차를 적는다.
- **CPU 격자를 거울로 둔다.** GPU 스텝 뒤 온도·면 속도를 CPU 배열로 내려받는다. 결합 다리·렌더링·장부·스냅샷 코드는 그대로이고,
  CPU FP64 경로는 같은 입력으로 비교하는 기준이 된다. 내려받기 비용(265680셀 x 4장 x 8바이트 약 8 MB/스텝)은 재서 필요하면 줄인다.
  열원·냉각은 0이 아닌 셀만 (인덱스, 값) 목록으로 올린다.

### 5. S5 마무리 (2026-09-27 사용자 결정: 기본 격자 0.25 m 유지, S5 마무리 → S6)

- 5a. 옥트리 경로 덕트(랙 팬 관통 기류·CRAH 유닛) 지원: 루트 덕트 면을 그 면 위에 놓인 옥트리 면(고체 리프 | 공기 리프)으로 옮긴다
  (위상이 바뀔 때만 다시 짝지음). 속도는 덕트 속도로 고정, 투영 우변에 공기 쪽만 플럭스를 넣고, 온도는 덕트별 흡기 혼합 → 코일 ε → 팬 dT를
  배기면이 싣는다(규약 6, 장부 유출 코일 / 유입 팬). CFL·발산 진단에 덕트 면을 넣는다. `FAirSolver`의 옥트리 덕트 거부와
  통합 액터의 "옥트리면 천장 코일로 대체"를 없앤다. 운동량은 열린 면으로만 이류한다(덕트 제트는 투영이 만든다 — 한계로 적는다).
  완료 조건: 옥트리 덕트 열수지·발산·유량 테스트, 깊이 0 옥트리가 균일 덕트와 같은 흡기 혼합 결과.
- 5b. A/B: 같은 방을 균일 0.25 / 옥트리(루트 0.25, 랙 주변 깊이 1 = 0.125) / 균일 0.125(GPU)로 돌려 흡기·비용 비교.
  옥트리와 균일은 운동량 이류가 달라 완전한 "같은 정확도 조건"이 아니다 — 그 한계와 함께 적는다.
- 그다음 S6.
