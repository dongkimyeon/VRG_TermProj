## S6 배치·센서·평가 (2026-09-27)

화면에는 단축키 안내만 두므로 결과는 **로그와 리포트 파일**로 낸다.

- **배치**: 배치 모드에서 `G`/`T`(잡기·회전, 1단계) + `C` 컨테인먼트 0/1/2 순환(다음 시뮬레이션 진입 때 적용).
  `vrg.Layout.Save/Load <이름>` — 랙·스파인·CDU·CRAH의 이름별 위치(m)·방향(도)과 냉각 설정(컨테인먼트·CRAH 배치·냉각수 방출·셀 크기)을
  `Saved/Layouts/<이름>.json`으로. 불러오기는 같은 이름의 액터를 옮기고(장비를 새로 만들지 않는다) 배치 모드로 바꾼다. 없는 장비는 로그로.
- **센서(D9 "모의 계측값")** `Simulation/Sensors/VirtualSensor.*`: 1차 응답 지연(시간 상수 τ, 스텝마다 정확한 지수 갱신), 샘플링 주기(판독 시각은
  스텝에 맞춰짐), 가우스 잡음(고정 시드, 센서마다 시드+번호), 분해능, 임계값·히스테리시스 경보와 첫 감지 시각. 흡기마다 하나씩 자동으로 둔다.
  기본값(τ 10 s, 1 s 주기, σ 0.1 K, 0.1 K 분해능, 27 °C 경보)은 **일반 서미스터를 가정한 값**이며 제품 사양이 아니다.
- **전력 분해(D8)**: IT(랙 부품 + 서버 팬 + PSU 손실) / CRAH 팬 / 펌프(수력 운전점 전기 입력). **부분 PUE = (IT + CRAH 팬 + 펌프) / IT** —
  칠러·냉각탑·UPS·배전 손실·조명은 모델에 없어 시설 PUE가 아니다. IT 0이면 계산 불가.
- **재실행**: 고정 시드 + 시뮬레이션 진입 때 초기화 + 시각 이벤트 `vrg.Eval.Event <t> util <v> | <t> rackutil <i> <v> | clear`(통합 시계,
  규약 4, 진입마다 다시 적용). 같은 입력 두 번이 같은 결과를 내는 것을 테스트로 건다(수치 비교이며 레이스 검증이 아니다).
- **리포트** `vrg.Eval.Report <이름>` / 무인 실행용 `vrg.Eval.ReportWhenDone <이름>`(예약 스텝이 끝나면): `Saved/Reports/<이름>.json/.md` —
  흡기별 창 평균(기본 마지막 100 s, 1 s 구간)·실행 평균·최고·27/32 °C 초과 시간, 센서 마지막 값·첫 경보, 전력·부분 PUE, 전역 열수지 분해,
  압력 풀이·실패 수, 이벤트. **A/B** `vrg.Eval.Compare <A> <B>` → `AB_<A>_vs_<B>.md`(IT 부하가 0.1% 넘게 다르면 D8 경고).
- 콘솔 명령을 `-ExecCmds`로 여러 개 줄 때는 **쉼표**로 나눈다(세미콜론은 한 명령으로 들어간다 — 실제로 겪었다).

L_Test 시연(0.25 m, 300 s, 150 s에 부하율 0.6 이벤트, 컨테인먼트 없음 대 블랭킹+지붕):

| | 흡기 창 평균 최고 | 평균 | 27 °C 초과 | 센서 경보 | IT | 부분 PUE | 전역 잔차 |
|---|---|---|---|---|---|---|---|
| 없음 | 28.25 °C | 24.58 °C | 2 | 4 | 2581 kW | 1.0144 | 5.1e-14 |
| 블랭킹 + 지붕 | 22.69 °C | 22.21 °C | 0 | 0 | 2579 kW | 1.0144 | 4.8e-14 |

**부분 PUE가 같다.** CRAH 풍량이 고정이고 공급 온도·풍량 제어가 모델에 없어, 컨테인먼트 이득이 흡기 온도로만 나타나고 전력으로는 안 나타난다.
전력 이득을 보려면 흡기 여유만큼 공급 온도를 올리거나 풍량을 줄이는 제어가 필요하다(다음 과제 후보). 보정되지 않은 모델의 결과다.
검증: 새 테스트 3건(오차 기준표). 전체 `VRG` **115 성공 / 실패 0 / 경고 0**.


## 2026-10-13 S7 웹 대시보드 1단계 (요약 카드)

엔진 HTTPServer를 127.0.0.1에만 연다(`vrg.Web.Enable`, 기본 끔, `vrg.Web.Port` 18080). `GET /api/snapshot`(SI 단위 JSON)과
`GET /dashboard`(`Web/index.html`, 엔진 라우터가 `/`를 못 묶는다). 게임 스레드가 Tick 끝에 0.5 s마다 요약 사본을 넘기고 핸들러는 사본만 읽는다(규약 5).

검증: `VRG.Web.DashboardSummary`(신규, 리포트 값과 정확 일치·서버 켬/끔), `VRG.Eval.RerunEventsAndReport` 성공. Editor -game 한 번에서

`FVrgEvaluation`이 SimTime 1 s 버킷을 닫을 때마다 흡기 최고·평균, IT, 제거열, 부분 PUE의 1 s 평균을 최근 600 s 링에 쌓는다(리포트 창과 같은 버킷,

## 2026-10-13 S7 웹 대시보드 3단계 (평면도)

## 2026-10-13 웹 대시보드 랙 탭 JSON 비용

원인 측정: 요청당 약 4 ms의 거의 전부가 고른 랙 상세(부품 613개) JSON의 `FJsonObject` 트리 생성이었다. 직접 문자열 쓰기 + `std::to_chars`(정확 왕복)로 바꿨다.
L_Test 같은 실행에서 요청당 3.86 → 0.40 ms(목록 0.518→0.078, 상세 3.340→0.324 ms, 200회 평균). 이전 구현은 `*ToJsonDom`으로 남겨 기준·비교용.
검증: 두 방식 출력 값 비트 일치·이스케이프 왕복 테스트 추가(`VRG.Web.DashboardSummary`), Editor -game 랙 탭 표시 확인. 상세는 `Tools/웹대시보드_계획.md`.

## 2026-10-14 웹 대시보드 3D 보기 1단계

요약 탭에 three.js 0.128 3D 방 보기(비스듬히 위, 회전·확대·이동). `/api/layout`에 장비 높이·밑면과 격자 Z 범위를 더했다(옛 리포트 호환, 선택 필드).
랙·스파인은 흡기 창 평균을 2D 평면도와 같은 색 범위로, 27 °C 초과 ▲. 벽 = 공기 격자 경계(표시 전용, 카메라 쪽 낮게). 장면은 배치가 바뀔 때만 다시 만들고 1초마다 색만 바꾼다.
세계 (X,Y,Z) → three (X,Z,Y)로 UE 위에서 본 배치·2D 평면도와 거울 없이 같다. 흐름·배관·센서·누수 레이어는 미구현. three.js는 CDN 의존(오프라인 미해결).
검증: `VRG.Web` 2건 성공, Editor -game에서 표시·조작·랙 클릭 이동·콘솔 오류 0 확인. 브라우저 렌더 비용 미측정. 상세는 `Tools/웹대시보드_계획.md`의 "3D 보기 1단계".

## 2026-10-14 웹 대시보드 3D 보기 2단계 (냉각수 배관)

방 액터가 배관 메시 경로(GJ 우회·포트·CDU→펌프 연결 포함)를 월드 m로 기록하고(`GetPipeRoutesM`), `/api/layout`에 배관별 경로·수력 해 유량·지름·온도를 싣는다.
온도는 모델에 값이 있는 랙 분기만(공급 = 랙 입구, 회수 = 랙 출구), 헤더·펌프 연결은 "모델 값 없음". 3D 레이어(켜고 끄기, 기본 켬): 굵기 = 실제 지름, 색 = 온도(주황 순차, 표시용 20~45 °C), 원뿔 = 유량 방향, 툴팁·배관 표.
검증: 신규 `VRG.Web.PipesMatchNetwork`(plain/GJ, 모든 배관 한 번·유량 정확 일치·온도 규칙) 성공. Editor -game L_Test: 배관 128(124+펌프 4), 온도 64, 분기 2.356 L/s. 상세는 `Tools/웹대시보드_계획.md`.
