# W3.5 내부 누수 조작·표시 직접 확인

## 현재 확인 범위

- 자동화: 135지점/앞뒤 조준/트레이 높이/회전·스케일/공랭 슬롯 제외, 이름 콘솔·이벤트·수리, 위상·배관 번호 유지, 상태 조회/센서/물/리포트 검증 성공. 기존 외부 누수 검사 포함 고유6건 최신 결과 성공.
- 실제 화면/입력: **미검증**. 확인용 L_Test 게임 창은 실행됐고 드라이버 안내 창이 검색됐다. computer-use의 `get_window`/접근 준비 중 `Computer Use app approval timed out`이 반환돼 중단했다. 아니오 클릭·게임 입력·스크린샷을 확인했다고 세지 않는다. 재시도하지 않았으며 이번에 띄운 게임 프로세스만 종료했다.
- 전체 테스트·FPS·새 패키징은 실행하지 않았다. 다음 절차가 정상이어도 W3.5의 나머지 완료 조건을 별도로 확인한다.

## 준비

1. 최신 소스를 빌드한 에디터에서 `/Game/Maps/L_Test`를 연다. 그래픽 드라이버 안내가 나오면 **아니오**로 닫는다.
2. Play를 실행하고 게임 뷰포트를 클릭해 입력 포커스를 준다. 에디터에서 시작한 경우 Shift+F1은 마우스 해제이므로, 테스트를 계속할 때는 뷰포트를 다시 클릭한다.
3. `Enter`로 시뮬레이션 모드에 들어간다. 배치 모드에서는 누수 도구가 작동하지 않는다. 패치/숫자 창은 닫는다.
4. 우클릭을 누른 채 WASD와 마우스로 랙 앞에 접근한 뒤 **우클릭을 놓는다**. 앞면은 컴퓨트 노드 전면이 보이는 쪽(+로컬 X)이다. 양옆 면은 내부 조준 대상이 아니다.
5. 선택 사항: 콘솔 키(보통 Esc 아래의 ` / ~)를 눌러 `vrg.Leak.Sites rack 0`을 입력하고 Enter를 누른다. 해당 랙의 135개 내부 지점과 key를 Output Log에서 확인한다. 콘솔을 닫은 뒤 조작한다. 랙/트레이 번호는 **0부터**, 트레이는 액랭 장비27대만 높이순으로 센 번호이며 전체37슬롯 번호와 다르다.

## 1. 앞면 조준과 지점 종류

1. `L`을 한 번 누른다. 누수 도구가 켜지고 커서가 보인다.
2. 커서를 앞면의 컴퓨트/NVLink 트레이 가운데에 둔다. 노란 표식과 `랙 N 트레이 NN … 냉각 플레이트` 안내, 좌상단 상태 패널이 나타나는지 본다. 아무것도 클릭하지 않았다면 물/센서는 건조·미감지여야 한다(실행 초기 센서는 잠깐 준비 중).
3. `B`를 차례로 누른다. **냉각 플레이트 → 공급 커넥터 → 회수 커넥터 → 냉각 플레이트**로 변해야 한다. 랙·트레이 높이는 그대로다.
4. 다른 컴퓨트 트레이로 커서를 옮겨 트레이 번호가 바뀌는지 확인한다. 전원 셸프/관리 스위치/빈 공간/측면에는 내부 지점이 선택되지 않아야 한다. 외부 배관 표식은 별도 W1 도구 동작이다.
5. `L`은 크기 모드를 **1mm → 3mm → 파단(기존 호스9.525mm) → 수리(0) → 끔**으로 순환한다. 외부 배관에는 기존5mm/30mm가 적용되므로 **내부 지점 이름과 내부 mm 안내를 먼저 확인**한다. 크기 선택만으로 구멍이 열리지는 않는다. 왼쪽 클릭할 때 적용한다.

## 2. 열기·물 이동·센서

1. 처음에는 낮은 컴퓨트 트레이의 냉각 플레이트를 고른다(높은 트레이는 아래 슬롯을 지나므로 도착이 늦다). `L`로 내부3mm를 선택한 뒤 왼쪽 클릭 한 번 한다.
2. 지점이 빨강으로 표시되고 구멍3mm가 기록되는지 본다. 유량은 수력 풀이 결과이며 클릭 즉시 값이 갱신되지 않고 다음 공유 스텝에서 반영될 수 있다. 물이 도착하기 전 센서 경보를 강제로 켜면 안 된다.
3. 아래 항목을 구분해 읽는다.
   - `선택 슬롯 현재 보유`: 그 슬롯의 현재 물. `뒤쪽 누적 노출`: 지나간 뒤쪽 접촉 이력이며 현재 재고와 합산하지 않는다.
   - `랙 현재 보유 + 이동 중`: 랙 안에 아직 남은 물.
   - `바닥 누적 도착 = W3 전달 + 대기`: W3가 아직 받지 못한 물도 도착량에 들어가며 두 번 더하지 않는다.
   - `트레이 냉각수 온도·입/출구`: 기존 열/수력 계산값. 역류는 부호를 유지한다.
   - `드립/로프`: 모의 계측값. 판독1s·응답1s, 드립30mL/로프 양의 국소 접촉은 추정이며 실제 장비 성능 보장이 아니다.
4. 보유 물이 있는 슬롯 앞면은 청록 테두리, 뒤쪽 누적 접촉만 있는 슬롯은 보라 테두리가 생기는지 본다. 3D 수막이 아니라 계산 이력의 디버그 표시다. 내부 물줄기/W2 분사는 만들지 않는다.
5. 드립은 바닥 도착량이 문턱을 넘어 판독/지연 조건을 충족한 뒤 감지해야 한다. 앞 슬롯 누수만으로 로프 감지를 강제하지 않는다. 다른 랙은 젖지 않았다면 경보가 없어야 한다. 자동화의2s/3s는 특정 누수·부하·장면 조건의 결과이므로 L_Test에서 같은 시간을 요구하지 않는다.

## 3. 수리와 뒤쪽 매니폴드

1. 커서를 같은 지점에 둔 채 `L`을 눌러 **수리(내부0mm)**로 만든 뒤 클릭한다. 다음 스텝 뒤 누수 유량0, 추가 입력 중단을 확인한다.
2. 남은 물은 즉시 사라지지 않고 아래로 계속 이동한다. 기존 드립/로프 경보와 최초 경보 시각은 유지돼야 한다. 수리는 배수/경보 해제가 아니다.
3. `Esc`로 도구를 끄고 우클릭 비행으로 랙 뒤로 이동한다. 우클릭을 놓은 뒤 `L`로 다시 켠다.
4. 컴퓨트 트레이 높이를 조준하면 기본 **공급 매니폴드**, `B`로 **회수 매니폴드**가 순환해야 한다. 이들의 표식 위치는 도식 앵커다.
5. 공급 매니폴드에 내부3mm를 클릭해 뒤쪽 누적 노출과 로프 감지가 계산되는지 확인하고 같은 지점을 수리한다. 앞쪽 드립은 바닥 도착량 기준을 그대로 따른다.

## 4. 입력 충돌·새 실행

1. 도구가 켜진 동안 `E`로 장비가 뽑히지 않는지 확인한다. `Esc`로 도구를 끈 뒤 기존 `E` 탈착이 정상인지 확인하고 다시 꽂는다.
2. 우클릭 비행 중 클릭이 누수를 만들지 않는지, 패치 창/콘솔을 열었을 때 도구 클릭·L/B가 적용되지 않는지 확인한다. 닫은 뒤 뷰포트를 클릭해 포커스를 돌려준다.
3. `Enter`로 배치 모드에 갔을 때 도구/패널이 사라지는지, 다시 시뮬레이션으로 진입하거나 `R`로 재시작하면 구멍·물·경보/감지 시각이 초기화되는지 확인한다(예약 누수 이벤트가 있으면 다시 적용되므로 clear 후 확인).
4. 이번 상태를 리포트로 확인하려면 도구를 끄고 콘솔에서 `vrg.Eval.Report W35_manual`을 실행한다. `Saved/Reports/W35_manual.json/.md`의 기존 경보 표와 instruments 센서 ID/랙/종류/시각을 비교한다. 이 파일들은 커밋하지 않는다.

## 위치 선택이 어려울 때의 보조 콘솔

먼저 시뮬레이션에 들어가고 콘솔을 연다. 아래는 랙0의 가장 낮은 액랭 트레이 예시다.

```text
vrg.Leak.Sites rack 0
vrg.Leak.At rack:0:tray:0:plate 3
vrg.Leak.Repair rack:0:tray:0:plate
vrg.Leak.At rack:0:tray:0:supply_manifold 3
vrg.Leak.Repair all
```

`plate/supply_connector/return_connector/supply_manifold/return_manifold` 또는 출력된 정확한 label을 따옴표로 감싸 사용할 수 있다.
`vrg.Eval.Event 1 leakat rack:0:tray:0:plate 3`은 **다음 실행**의1s에 적용되는 예약 예시다. 끝나면 `vrg.Eval.Event clear`로 지워 다음 실행에 반복되지 않게 한다.
기존 `vrg.Leak.At x y z mm`/좌표 leakat은 계속 **외부** 지점을 선택한다. 내부 위치는 key/label로 명시한다.
이 콘솔 경로의 성공만으로 실제 커서·L/B/클릭·포커스를 확인했다고 세지 않는다.

직접 확인 후 위1~4절별로 `[정상/문제와 관찰 내용]`을 알려주면 사용자 확인으로 반영한다.
