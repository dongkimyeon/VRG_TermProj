# L_Test 단일 드래그 입력 수동 확인

2026-10-04: 도구의 드라이버 안내 버튼 입력이 `coordinate input geometry is unavailable`로 실패해 같은 입력을 반복하지 않았다. 게임 시작 전이므로 이번 실행에서 드래그/Undo/Redo를 실제 확인하지 못했다. 기존 두 번의 drag 실패와 뒤 Ctrl+D 거절의 원인도 아직 미확정이다.

## 직접 확인할 순서

1. 현재 드라이버 다운로드 안내에서 **아니오**를 눌러 L_Test를 시작한다. 배치 모드인지 확인한다.
2. 콘솔(`~`)에서 `vrg.Layout.InputDiagnostics 1`을 실행하고 콘솔을 닫는다.
3. 랙 한 대를 왼쪽 버튼으로 **1초 정도 누른 채**, 빈 바닥으로 옮겨 주황 목적지가 보이면 놓는다. 목적지에 랙이 실제 이동했는지 확인한다. 빨강이면 놓아도 이동하지 않아야 한다.
4. `Ctrl+Z`로 원위치, `Ctrl+Y`로 목적지 복원을 확인한다. 이어 `Ctrl+D` 미리보기가 시작되면 `Esc`로 취소한다. 복제는 확정하지 않는다.
5. 단일 랙을 기존 줄 끝 가까이 옮겨 가이드가 보이면 놓고 `Ctrl+Z/Y`로 줄 붙이기 전후 위치·방향을 확인한다. 간격/줄 방향은 실제 기존 줄에서 구한다.
6. 다시 이동 미리보기 중 버튼을 누른 채 `Esc`를 누르고 버튼을 놓는다. 위치와 Undo/Redo 기록 수가 취소 전과 같은지 확인한다.
7. 콘솔에서 `vrg.Layout.InputDiagnostics 0`으로 끈다. 결과는 `Saved/Logs/DragInput_UI.log`(현재 진단 실행) 또는 평소 실행의 `VRG_TermProj.log`에 남는다.

1초는 사람이 관측하기 위한 조작 예이며 제품 입력 시간 조건이나 물리 수치가 아니다. FPS/열수지 측정은 이 절차에 포함하지 않는다.

## 로그를 읽는 기준

- `[VrgLayoutInput]`: 포커스·콘솔·패치·좌표/바닥 교점·복제/추가 상태. `[VrgLayoutGesture]`: LMB·drag 수·moved·4px threshold·row·marquee·G·Undo/Redo·실제/시작/목적지 cm·yaw.
- `RawLmbPressBefore/ReleaseBefore`: 이벤트가 컨트롤러에 도달한 증거. **Super::InputKey 이전**의 LMB 상태이므로 누름 로그의 LMB0 자체를 실패로 판단하지 않는다.
- `EnhancedSelectArmed` → `DragMoveThreshold` → `EnhancedReleaseBegin` → `DragEndCommitDone`: 처리 경로. `CommitDone`은 요청 처리가 끝났다는 뜻이며 성공 판정은 이동 확정 로그·실제 위치·Undo 수 증가로 한다.
- `TickNoLmbCancel`, `DragFocusCancel`, `DragEndCancelDone`: 확정 대신 취소된 경로. `EnhancedCancelBegin`은 Esc와 왼쪽 액션 Canceled의 공통 핸들러라 이 이름만으로 입력 원인을 구분하지 않는다.
- `Ctrl+D` 시 drag/마키/G/RMB/패치/콘솔/선택 수를 읽는다. 같은 사건의 누름/놓기 전후 로그가 없으면 이전 거절을 소급 단정하지 않는다.

자동화는 진단1 상태의 드래그·이동 Undo·줄 붙이기·복제4건 성공(무경고3+기존 축 근사 경고2 동반1)이다. OS 입력이나 실제 화면 검증을 대신하지 않는다. 제품 동작 변경은 하지 않았다.
