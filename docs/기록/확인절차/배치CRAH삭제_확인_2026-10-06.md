# 단일 CRAH 삭제 직접 확인 (2026-10-06)

인로우 추가·저장은 사용자 모두 정상 보고다. L_Test 런타임 인로우 추가→Delete→Ctrl+Z/Y와 복원/제거 화면은 직접 확인했다. 기존/전환 장비·충돌/차단·삭제 저장 UI와 FPS는 미검증이다. 실행 월드에서 확인하고 레벨을 저장하지 않는다. 드라이버 안내는 아니오로 진행한다.

1. 인로우를 추가해 실제 CRAH를 만든 뒤 한 대 선택→Delete→Ctrl+Z/Y로 삭제·복원·재삭제, ID/설정/변환과 선택 정리를 확인한다.
2. 기존 레벨 배치 CRAH와 자동 전환 CRAH도 검사한다. 전환된 원래 접촉 위치에서 Undo는 복원되고, 이웃을 옮겨 충돌시키면 Undo는 거절되고 기록이 남아야 한다.
3. 이동/R→Delete→Ctrl+Z 세 번→Ctrl+Y 세 번으로 이전 참조 재연결을 확인한다.
4. 미선택/다중/혼합 선택, 드래그/사각형/추가 미리보기/패치/시뮬레이션 중에는 CRAH 삭제가 없어야 한다. 기존 다른 종류의 삭제 기능은 유지된다.
5. 마지막 실제 CRAH를 삭제하면 기존 자동 쿨러 표시/냉각 계획이 돌아온다. Undo하면 삭제한 실제 한 대 구성으로 돌아온다. 냉각을 완전히 끄는 동작이 아니다.
6. 삭제 전후 파일을 각각 저장한다. 같은/새 L_Test에서 삭제 후 파일을 반복 Load해 삭제 반영·중복 없음·기록 초기화를, 삭제 전 파일로 복원을 확인한다(저장 지원 최종 결과는 CLAUDE.md 후속 절).
7. 시뮬레이션의 쿨러/풍량/팬/냉각 표시를 확인한다. 개수가 줄어도 풍량0 장비의 기존 총풍량 분담 정책은 유지된다. 물리/FPS 판정은 화면만으로 하지 않는다.

결과 전달: `단일 CRAH 삭제 직접 확인 결과: 모두 정상` 또는 실패한 단계/관찰. 캡처는 기존 Alt+Print Screen→클립보드 PNG 저장→이미지 확인.


## 이번 실제 확인 기록

일반 L_Test 창에서 인로우 버튼·빈 목적지 확정·런타임 CRAH Delete(1대)·Undo(1/1)·Redo(2/0)를 확인했다. Alt+Print Screen PNG에서 Undo의 복원과 Redo의 제거를 확인했다. 이후 Undo 두 번(0/2)으로 확인용 변경을 취소했다. 기존 캡처 API 호출/드라이버 설정 변경/레벨 저장/FPS 측정 없음. 저장 deletedCrahs는 Automation 완료이며 위6번 실제 UI 절차는 남는다. 근거는 CLAUDE.md 최신 절의 Saved 파일들(커밋 제외).
