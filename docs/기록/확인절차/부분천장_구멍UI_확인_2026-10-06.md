# 선택 판 구멍 추가 UI 직접 확인

신규 실제 버튼·숫자 창·선 색상·OS 포커스는 자동화와 별도로 아래 절차로 확인한다. 기존 실패 화면 도구는 재시도하지 않았고 FPS는 측정하지 않는다. 구멍은 해당 판의 내부 유동 개방 계획이며 다른 판/벽/장비/지붕이나 외부 배기를 제거하지 않는다.

1. L_Test를 실행하고 Enter로 배치 모드에 들어간다. 숫자 창과 패치를 닫는다. 기존 정상 확인한 수동 방을 사용한다. 초기 배치용 시험 예시는 방 X[-4,10]m·Y[-3,8]m·높이3.75m다. 방 검증이 거절되면 표시된 장비/CRAH/덕트 필요 범위를 포함하도록 확장하고 적용한다. 방 셀 크기는 바꾸지 않는다.
2. 기존 ‘부분 천장 추가’에서 시험 판 X[-3.75,-2.75]m·Y[-2.75,-1.75]m·높이3.0m를 한 장 추가한다. 합성 시험 기하이며 기본값/시설 규격이 아니다. 현재 장비/덕트와 겹치면 기존 검증 이유에 따라 빈 곳으로 옮긴다. 같은 위치에 중복 판은 만들지 않는다. 창을 닫는다.
3. 하단 세 번째 줄의 ‘선택 판 구멍 추가’는 판 선택 전에는 비활성이다. ‘천장 선택·삭제’를 켜고 카메라를 판 위에서 비스듬히 내려다보게 한 뒤 판 내부를 클릭 후 놓는다. 초록 강조를 확인한다. 모서리/중앙 핸들을 드래그하지 않는다. 구멍 버튼이 활성화되면 누른다.
4. 제목이 ‘선택 판 구멍 추가 (로컬 m)’이고 네 입력만 보여야 한다. 높이 입력/자동 모드 체크는 없어야 한다. 안내의 판 최소 XY·크기·높이를 확인한다. 예시 판의 로컬 최소 X=0.125, 최대 X=0.875, 최소 Y=0.125, 최대 Y=0.875를 입력한다. 아직 목록/판/Undo 기록은 바뀌지 않아야 한다.
5. ‘추가’를 한 번 누른다. ‘구멍 하나 추가됨’과 로컬 범위, 요청 월드 XY[-3.625,-2.875]×[-2.625,-1.875]m·높이3m를 확인한다. h0.25m·방 원점(-4,-3,0)m의 예시는 실제 개방 XY[-3.5,-3]×[-2.5,-2]m·Z[3,3.25]m의4셀이다. 판 외곽16셀/해당 판 제외4셀/남은12셀과 개방 범위·4셀 표시를 확인한다. 현재 방 원점/h가 다르면 숫자는 달라지므로 창의 계산 결과를 기준으로 본다. 다른 고체가 통로를 막을 수 있다는 안내도 있어야 한다.
6. Esc 한 번 또는 닫기로 숫자 창만 닫는다. 천장 편집과 선택은 유지되고 입력/커서가 복귀해야 한다. 판 내부에 청록 요청 윤곽과 보라 개방 계산 상자가 구분되어야 한다. 실제 메시를 잘라내거나 외부로 바람이 배출되는 기능은 아니다. 오른쪽 마우스 카메라 이동과 기존 판 선택/핸들 조작은 창을 닫은 뒤 정상이어야 한다.
7. Ctrl+Z로 구멍 하나만 제거되고 Ctrl+Y로 복원되는지 확인한다. 기록 복원은 기존 규칙대로 판 선택을 해제하므로 다시 선택해서 창을 연다. 입력을 바꿨다가 Esc로 닫으면 추가/기록은 늘지 않아야 한다.
8. 다시 창을 열고 최대 X를1.1로 바꿔 추가하면 판 밖 이유와 거절이 표시되고 이전 구멍이 유지되어야 한다. 네 값 모두 최소0.125/최대0.2로 입력하면 h0.25m에서 완전 포함 개방 셀0개 이유로 거절되어야 한다. `nan`이나 빈 입력도 거절되어야 한다. 입력 중 R/Delete/Ctrl+D/Ctrl+Z/Y/Enter가 장비·판·시뮬레이션을 조작하지 않아야 한다.
9. 패치를 열거나 시뮬레이션 모드로 전환하면 미확정 창을 취소해야 한다. 다음 시뮬레이션 진입에서만 확정 구멍의 고체 셀 개방이 적용된다. 배치로 돌아와 콘솔(~)에서 `vrg.Layout.Save CeilingHoleUiCheck`를 실행한다. Undo로 구멍을 없애고 `vrg.Layout.Load CeilingHoleUiCheck`로 복원한다. 성공 Load는 창/선택/공유 기록을 초기화한다. 새 실행에서도 같은 Load로 판·구멍이 복원되어야 한다.
10. 다른 고체 보존 확인은 원래 판과 동일한 구멍 없는 판을 겹쳐 추가해 볼 수 있다. 구멍 계획 선은 계속 보여도 중복 판이 그 셀을 막는다. 보라색은 해당 판에서 제외하는 계획 표시이며 최종 통로 개방 보장이 아니다. 이 사례는 자동화도 검사한다.

보고 예: `부분 천장 구멍 추가 UI 직접 확인 결과: [정상]` 또는 실패 단계와 표시된 문구/예상·실제 동작. 기존 부분 천장 전체 XY 이동의 사용자 정상 보고와 이번 신규 UI 미확인을 구분한다.
