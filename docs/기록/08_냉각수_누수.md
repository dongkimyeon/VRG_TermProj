# S2b 냉각수·누수·장애 기록

S2b 단계별 작업 기록이다(2026-10-20부터). 계획·단계별 상세 결과는 `Tools/S2b_누수_계획.md`, 오차 기준은 `docs/오차기준.md`의 "S2b" 절.

## 2026-10-20 S2b 계획과 높이(정수압) 단계

팀장 결정으로 S2b를 웹 대시보드보다 먼저 한다(`Tools/S2b_누수_계획.md`). 팀이 높이차 선택지 **B**(노드 높이 + 정수압 항)를 정했고, 높이 단계를 누수보다 먼저 했다.
`FHydraulicNode::ElevationM`, 배관·펌프는 피에조 압력 `P + ρgz`의 차를 쓴다(미지수는 정압, 펌프 곡선은 피에조 상승). 높이 0이면 기존 결과와 비트 동일.
ρ는 통합 액터 `CoolantDensityKgM3` 한 출처(망 기본 997), g = 9.80665. 방 액터가 노드 높이를 그려진 배관 끝점 높이 평균으로 정한다.
신규 `VRG.Hydraulics.Elevation.*` 3건 포함 영향 37건 성공·경고 0. 닫힌 루프 순환 유량은 높이와 무관(4.7e-17)이라 L_Test 냉각 결과는 바뀌지 않는다. 오차 기준표에 추가.

## 2026-10-20 S2b 1단계: 누수 오리피스

수력 압력은 모두 **계기압 Pa(g), 대기 0**으로 정의했다(기존 결과는 차만 써서 불변). `FHydraulicLeak`: `Flow = Cd·A·√(2(P−P_amb)/ρ)`, 역류 없음,
`R_leak = ρ/(2(Cd·A)²)`로 배관과 같은 꼴(D3 Newton 그대로). `Cd` 0.61은 날카로운 오리피스 교과서 값이며 실제 균열에는 추정값이다.
`SplitPipe`로 배관 중간에 누수 노드를 넣는다(유량 불변). 신규 `VRG.Hydraulics.Leak.*` 2건 포함 영향 27건 성공·경고 0, 수치는 오차 기준표.
**방·시뮬레이션에는 아직 연결하지 않았다.** CDU 고정 노드가 무한 저장소라 지금은 정적 상한 해이며(10 mm 분기 누수 1.175 L/s = 펌프의 6.2%, 펌프 유량이 오히려 늘어남),
2단계 재고·팽창탱크에서 고친다. 상세 `Tools/S2b_누수_계획.md` "1단계 결과".

## 2026-10-20 S2b 2단계: 팽창탱크·재고·보충수

줄마다 CDU 기준 노드를 팽창탱크(등온 기체 쿠션 `P_abs·V_gas = P_pre_abs·V_tank`)로 바꾸고, 통합 시계 스텝마다 명시적 오일러로 탱크 물을 줄인다(`Simulation/Hydraulics/CoolantInventory.*`).
**누수가 열려 있거나 보충 중일 때만** 그 스텝의 탱크 압력으로 수력망을 다시 풀고 결합 다리가 같은 스텝에 새 유량을 읽는다. 누수가 없으면 풀이 0회·기존 결과 그대로.
재고 고갈 = 그 줄 펌프 0·누수 닫음·탱크 0 Pa(g)(2상 거동 없음). 새 진입 때 탱크를 다시 채운다. 루프 물 부피는 쓰지 않는다(비압축·강체 관이면 탱크만 압력을 정함).
기본값은 **추정**이다: 탱크 24 L, 사전 충전 = 충전 − 0.3 bar(팽창탱크 안내서의 EN 12828 관계를 CDU에 적용), 보충 끔·상한 0.1 L/s. CDU 탱크의 공개 사양은 찾지 못했다.
콘솔(배치 모드): `vrg.Leak.Add <랙 번호> <supply|return> <mm> [Cd]`, `vrg.Leak.Size`, `vrg.Leak.Clear`, `vrg.Leak.Status`. 누수는 저장하지 않는다.
**고친 결함:** 수력 시작값을 방 전체 고정 노드 평균에서 루프별 자기 고정 노드 평균으로 바꿨다. 한 줄만 고갈되면 정지 루프가 먼 값에서 출발해 Newton이 유량 0 근처에서 멈췄다(D2). 줄마다 같은 압력이면 시작값이 이전과 같다.
검증: 신규 `VRG.Hydraulics.Inventory.*` 3건 포함 영향 34건 성공(NullRHI), 수치는 오차 기준표. L_Test -game: 3 mm 공급 분기 누수로 탱크 200 → 171 kPa(g), t=21.72 s 고갈, 30 s 전역 잔차 3.29e-14,
재풀이 스텝당 약 0.40 ms(노드 101, 밀행렬 LU, 결합 스텝 11.2 ms의 3.6 %, 측정값). 화면 확인 안 함. 누수 열 장부는 3단계. 상세는 `Tools/S2b_누수_계획.md`의 "2단계 결과".

## 2026-10-20 S2b 3단계: 누수 열과 전역 장부

결합 다리가 랙 분기 누수 유량(수력 해, kg/s로 한 번 변환)을 읽고, 누수 열 `Σ L·cp·(T_leak − T_tank)`를 `CloseCoolantLoop`에서 **한 번만** 계산해 전역 장부 유출에 더한다(규약 6).
CDU 열교환기는 펌프 유량(랙 합 + 공급 누수)과 탱크 보충수가 섞인 혼합 온도를 보므로 `랙 → 냉각수 열 = CDU 부하 + 누수 열`이 항등적으로 닫힌다. 랙별 라디에이터 줄도 같다.
`T_leak` = 공급 분기면 랙 입구, 회수 분기면 랙 출구. `T_tank` = 직전 스텝 공급 온도(근사, 탱크 열용량 없음). 누수가 없으면 결과 비트 동일.
고갈은 "냉각수 유량 0"까지만 다룬다(랙은 자기 열용량으로 데워짐, D2). 신규 `VRG.Hydraulics.Inventory.LeakHeatLedger` 포함 영향 21건 성공, 수치는 오차 기준표.
L_Test -game(회수 3 mm): t=25.56 s 고갈, 30 s 누수 열 50.3 kJ, 루프 장부 차 −8.6e-8 J, 전역 2.68e-14. 화면 확인 안 함. 상세 `Tools/S2b_누수_계획.md` "3단계 결과".

## 2026-10-20 S2b 4단계: 밸브 격리

`FHydraulicPipe::bClosed`: 닫힌 배관은 풀이에서 빠지고(큰 저항이 아님) 유량 0, CDU와 끊긴 노드는 미지수에서 빠져 대기에 열린 값(피에조 0)으로 표시하며 그 구간 누수도 0이다.
랙 분기마다 공급·회수 밸브 한 쌍(`SetRackValveClosed`, `vrg.Valve`, 이벤트 `vrg.Eval.Event <t> valve <i> close|open`). 보고서가 **격리 범위**(위상)와 **수력 영향 범위**(재계산 유량 변화 > 표시 문턱 1e-3)를 따로 낸다(D4).
닫은 해는 그 분기를 처음부터 뺀 망과 상대 차 0, 다시 열면 원래 해. 새 진입 때 모든 밸브를 연다. 신규 `VRG.Hydraulics.Valve.*` 2건 포함 영향 49건 성공, 수치는 오차 기준표.
L_Test -game: 5 s 이벤트로 랙 3 닫음 → 격리 [3], 영향 = 같은 줄 7대(+7%), 다른 줄 변화 0, 펌프 17.365 L/s(기존 "랙 3 비움" 기록과 같음), 누수 정지, 전역 3.28e-14. 화면 확인 안 함. 상세 `Tools/S2b_누수_계획.md` "4단계 결과".

## 2026-10-20 S2b 5단계: 장애 판정·이벤트·리포트

`FVrgFaultMonitor`가 스텝마다 **계산 결과로만** 판정한다(D4): 저유량(설계 유량 = 누수 닫고 밸브 연 수력 해, 비율 0.5는 표시용), 과열(부품 최고 온도 > 85 °C **추정값**, 공개 Tj 최대 못 찾음), 재고 고갈, 수력 실패. (랙, 종류)별 첫 시각만 기록, 탱크 이력 1 s 표본.
이벤트 `vrg.Eval.Event <t> leak <랙> <supply|return> <mm>`(진입 때 닫힌 구멍을 미리 만들어 t에 엶). 리포트 JSON 선택 필드 `s2b`(옛 리포트 호환).
곁가지 수정: 줄이 완전히 멈추면 반올림 수준 압력차 때문에 수력이 수렴 실패로 남았다 → 피연산자 8 ULP 이하의 피에조 압력차는 0(`PiezometricDropPa`).
신규 `VRG.Hydraulics.Fault.*` 2건 포함 영향 57건 성공. L_Test -game: 2 s 누수 → 10 s 밸브 → 10.02 s 랙 3 저유량 판정, 리포트 s2b 기록, 전역 2.28e-14. 화면 확인 안 함. 상세 `Tools/S2b_누수_계획.md` "5단계 결과".

## 2026-10-20 S2b 6단계: 웹 누수 레이어, 이벤트 경로 결함 수정

`GET /api/leaks` + 3D 레이어(누수점·탱크·격리 실선/수력 영향 점선·판정 표식·표). 이미 계산된 값만 복사하며 판정기 입력은 `MakeFaultInput()` 하나를 판정과 대시보드가 같이 쓴다.
**결함 수정:** `-ExecCmds` 첫 프레임 진입에서는 방이 랙 줄을 아직 만들지 않아 누수 구멍 준비가 건너뛰어졌고, 이벤트 때 방을 실행 중에 다시 지었다. 나눈 분기 뒤쪽 줄의 배관 번호가 밀려
결합이 그 줄 랙에 헤더 유량(최대 7배)을 넘겼고 탱크도 다시 채워졌다(L_Test에서 랙 24 오판정으로 드러남). 진입 때 방을 먼저 짓고, 실행 중에는 누수 사양 추가·삭제를 막는다(`SetLeakTopologyLocked`).
5단계 L_Test -game 결과는 이 결함을 포함했을 가능성이 높다(미확인, 판정 결론은 수정 뒤에도 같음).
신규 `VRG.Web.LeaksMatchModel`·`VRG.Web.LeakEventKeepsRowMapping` 포함 영향 54건 성공. L_Test -game: 실행 중 재구축 0회, 결합/분기 = 997 kg/m³ 하나, 줄 2 고갈 6.42 s, 과열 판정 83.6 s(줄 2)·85.02 s(랙 3).
페이지는 AI 화면 확인(Chrome, 합성 포인터 툴팁), 콘솔 오류 0. 상세 `Tools/S2b_누수_계획.md` "6단계 결과". S2b 단계 완료.

## 2026-10-22 계측 지점과 센서 누수 감지 (사용자 요청)

모든 그린 배관(방 TCS, 설비 FWS·CHW·CW)에 `vrg.Sensors.PipeIntervalM`(기본 3 m, 추정) 간격으로 계측 지점을 둔다(`FInstrumentBank`, `DataCenterSimulationInstruments.cpp`).
지점마다 유량·수온(모의 계측값, D9)과 누수 감지 케이블 구간(덮는 반경 = 구간 반 + 0.3 m, 게임용 추상화)이 있다.
- 감지(D4): 풀린 누수 유량을 시간 적분해 덮는 구간에 흘러나온 물이 0.5 L(추정)를 넘으면 젖음, 1 s 주기로 읽고 경보를 유지(물은 저절로 마르지 않음). 1 mL/s 미만은 퍼지기 전에 증발로 보고 무시(추정).
  처음에는 "10 s 젖는 지연 + 누수가 멈추면 마름"으로 만들었는데, 시험의 작은 탱크(2.4 L)가 6.6 s 만에 고갈돼 누수가 멈추자 감지가 사라졌다. 흘러나온 물의 양으로 바꿨다.
- 누수 위치: 방은 분기 중간 노드(`NodePositionM`), 설비는 마당 도식의 노드 위치. 위치가 도식이라 "어느 지점이 감지했는가"도 도식 기준이다.
- 경보는 로그 `[Sensor] 누수 감지 t=…`와 뷰포트 빨간 라벨(거리 무관). 리포트·웹 대시보드에는 아직 없다.
- 검증: `VRG.Sensors.Instruments.LeakCableAndChannels`(0.2 L/s → 0.5 L 뒤 첫 판독 15.00 s, 반경 밖 침묵, 미만 물방울 무시, 유지),
  `PlantAndRoomLeaks`(방 5 mm 약 0.36 L/s: 2 s에 8곳, 지점-누수 최대 1.28 m / 설비 10 mm: 1 s 뒤 4곳). L_Test(`vrg.Leak.Add 3 supply 5`)에서 2 s에 감지(로그·AI 화면 확인).
- 2026-10-23: 리포트에 계측 지점 수·누수 케이블 수·누수 경보 표(md "누수 감지 센서", json `instruments.leakAlarms`). 유량계에 저유량 차단(기대 유량의 1 %, 추정): 닫힌 대기 분기가 잡음으로 −0.02 L/s처럼 보이던 것을 0으로.

## 2026-10-23 실시간 누수 W1 (`Tools/누수_실시간_계획.md` "W1 결과")

시뮬레이션 중에 누수를 낼 수 있게 했다. 방을 지을 때 랙마다 닫힌 잠재 지점 3개(공급·회수 분기 중간, 공급 헤더 티)를 미리 넣고, 실행 중에는 구멍 크기만 바꾼다.
위상과 배관 번호가 바뀌지 않아 2026-10-20 이벤트 경로 결함(실행 중 재구축 → 결합 번호 어긋남)과 같은 부류의 위험이 없다. 설비는 기존 노드 누수를 `FFacilityPlant::SetLeakAt`(장애 경로, D4)로 연다.
- 닫힌 지점이 결과를 바꾸지 않는지: 지점 없는 같은 방 대비 유량·열량 상대 3e-14, 온도 1e-13 K. 닫힌 지점은 재고 풀이를 깨우지 않는다.
- 보이는 누수 정의(`IsLeakSpecShown`): 잠재 지점은 이번 실행에서 열린 적이 있을 때만 웹·탱크 누수 수·`vrg.Leak.Status`에 나온다. 이 때문에 `Web.LeakEventKeepsRowMapping`의 사양 수 기대를 4 → 4×3으로 고쳤다(이벤트 `leak`이 랙 0의 잠재 공급 분기를 차지하는 설계 변경, 검사 자체는 그대로).
- 겪은 것: 설비 표시용으로 지어진 설비(F7b, Enable 0)에서도 지점이 28개 잡혀 설비 지점은 설비 열 계산이 켜졌을 때만 둔다. 헤더 누수 열 부호를 양으로 기대했는데 공급수가 탱크 기준보다 차가워 음이 맞다(기대를 고침).
- 시험 탱크(2.389 L)는 5 mm에서 약 7 s 만에 고갈된다. 고갈 뒤에는 기존 S2b 동작대로 펌프 정지·누수 닫음이라 그 줄의 지점을 다시 열어도 바로 닫힌다.
- 검증: 자동화 `VRG.Hydraulics.LiveLeak` 4건, 전체 `VRG` 296건 성공. L_Test 로그(지점 96 / 설비 켬 136, `leakat`, 재구축 0, 리포트 `pointM`)와 AI 화면 확인(L 도구 표시·순환·클릭·수리·Esc·배치 모드). 수치는 `docs/오차기준.md` "실시간 누수 W1".
## 2026-10-26 실시간 누수 W2: 분사 (`Tools/누수_실시간_계획.md` "W2 결과")

구멍에서 나간 물을 계산한다(`FLeakSpray`): 분출 속도 Cv·√(2Δp/ρ), 물줄기 → 분열 길이(Grant & Middleman) → 액적(Rayleigh·임계 We), 구 항력, 장비·벽·천장 판·방·땅과의 충돌,
Mundo 문턱 튐, 아래 면 물방울, 수직면 Nusselt 물막, 바닥 0.1 m 칸(W3 원천). 방향 기본값은 지점 위치를 씨앗으로 한 아래쪽 원뿔(2026-10-26 사용자 결정), 표시는 자체 디버그 점(실제 물 표시는 W6).
